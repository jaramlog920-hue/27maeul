# 저장·통합 및 실제 브라우저 재검증 (2026-10-19)

기존 `report.md`는 10월18일 상태의 역사적 기록이다. 중단 중 외부 수정이 있어 현재 소스 기준으로 다시 검사했다. 이 감사에서는 기존 소스·설정·기존 테스트를 수정하지 않았다.

## 현재 판정

이 담당 범위에서 현재 새로 확정한 미해결 결함은 없다. 발견하지 못했다는 뜻이며 무결함을 보장하지 않는다.

- R-M1: 장면 오류 닫기 반복은 `ScreenBoundary`의 `skipBrokenScreen` 호출로 해결됐다. 동일한 `welcome` 렌더 장애를 주입하고 닫은 뒤 다음 프레임에 장면이 다시 열리지 않는 것을 실제 React/jsdom에서 확인했다. 이는 장애 복구 시험이며 정상 welcome이 원래 오류를 냈다는 주장은 아니다.
- R-L1: 잘못된 coins/hearts 문자열은 `save.normalizeShapes`에서 정규화한다. coins=`"50"`는0, hearts.baker=`"50"`는 제거되고 실제 1점 인사가1점이 되는 것을 확인했다.
- 정상123닢 저장과789닢 백업 가져오기는 서로 다른 저장 칸으로 유지된다.
- `current-results.json`: 4개 검사 모두 통과. 마지막1개는 비공개 사용자 정보가 전혀 없는 브라우저용 시험 백업을 생성·유효성 검사하는 작업이다.

## 실제 프로덕션 브라우저 UI

`current-build`를 127.0.0.1:52793의 새 origin에서 실행했다. 시작 전에 ‘이어하기/불러오기’가 없는 빈 타이틀을 확인했다. 다른 로컬 포트4180에는 기존 시험 저장이 있어 읽기만 하고 시험에 사용하지 않았다.

1. 타이틀 → 새로 시작하기: 빈 이름에서 시작 단추 비활성.
2. 공백3개 입력: ‘이름을 적어 주세요’ 및 시작 비활성 유지.
3. `감사시험` 이름으로 생성 → 실제 canvas 게임 및3단계 시작 안내 확인.
4. 메뉴 → 설정 → 기록 → 저장하기: ‘새 칸에 저장했어요’ 확인.
5. 타이틀로 → 불러오기: 원래 칸과 수동 저장 사본의 이름·1일째·0닢 확인.
6. 375×812 viewport로 사본 로드:1일째06:10 및 저장한 상태로 복원. 실제 canvas 그림과 조작판이 그려지고 가로 넘침 없음(document/body scrollWidth=375, innerWidth=375).
7. 설정 → 기록 → 붙여넣기: 자체 생성한 `browser-import.json`(이름 가져오기검증,7일째,789닢)을 browser clipboard로 입력. 가져오기 완료 알림과 자동 새로고침 확인.
8. 불러오기 목록: 가져오기검증7일째789닢과 기존 감사시험1일째0닢 두 칸이 모두 존재. 가져온 칸을 열어7일째10:00·789닢을 다시 확인.
9. 저장하고 타이틀로 복귀. viewport 임시 설정 원복. 이 페이지에서 수집한 console warning/error는0개였다.

증거: `browser-save-proof.png`. 실사용 저장·외부 계정·결제·삭제는 실행하지 않았다. 테스트 시작 전 로컬 주소 열기 외 외부 URL 요청/전송을 직접 호출하지 않았다.

## 범위·한계

루트 담당 production 모듈/설정 및 통합 경로를 검토했다. coverage-current.json은 agent 보고서와 병합한 파일별 검사 깊이를 기록한다. 마지막 누락5개(`scroll`, `word-options`, `LetterBox`, `TipLetterView`, `scroll-hint`)도 원문 전체와 호출 의미를 읽었다. 개발용 test-saves/controls-playtest는 DEV 가드와 새 시험 칸 경로를 읽었으며 운영 빌드의 시험 훅 활성화를 주장하지 않는다.

화면 이동과 저장 핵심 경로는 실제 브라우저로 확인했지만 모든 게임 화면·모든 모바일 운영체제·키보드·음성 인식·실제 서비스워커 업데이트/오프라인 장애·강제 종료를 전수 UI 시험하지는 못했다. quota/동시 저장·오류 복구의 기존 회귀 테스트는 전체 suite 결과에 포함하며 실제 기기의 용량을 채우는 시험은 하지 않았다.
