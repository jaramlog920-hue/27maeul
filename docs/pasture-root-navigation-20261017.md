# 양우리 끊김 원인 재조사와 경로 처리 수정 — 2026-10-17

## 이전 설명 정정
앞선 네 방향을 인위적으로 막은 성능 측정은 일반 경로 탐색 병목을 확인한 검사였으며 사용자가 겪은 비 오는 날 현상 자체의 증거는 아니었다. 0.5초 재시도도 원인을 제거하지 않았다. 실제 일과 전환을 포함해 조사했다.

## 실제 게임 상태에서 잡힌 조건
자율 생활이 열린 진행에서 06:39에 시작해 06:40 출근 시간을 통과하도록 실제 `tick`을 호출했다. 맑은 날(1일)과 비 오는 날(3일)을 비교했다.
- 플레이어 (10,30): 실패 경로 없음.
- 플레이어 (5,27) 또는 (5,28): 양우리로 들어오려는 주민이 경로를 찾지 못했다.
- 실제 목표: 맑은 날 (6,29), 비 오는 날 (5,30). 출발지는 양치기 문 앞 (43,24) 및 연결된 실내 (14,132)였다.
- NPC 산책 경로에 플레이어 칸을 고정 장애물과 함께 넣었기 때문에, 좁은 입구에 서 있는 플레이어가 양우리 전체를 단절시켰다. 목적지 변경·문 이동 실패 뒤에도 같은 목표로 전역 경로를 반복 탐색했다.
- 비에서만 발생하는 조건은 아니었다. 비 오는 날의 양우리 목표와 플레이어 위치 조합에서도 재현된다.

## 원인 처리
`game.tick`에서 가구·잠긴 길 등 고정 장애물과 플레이어의 일시 점유를 분리했다.
- NPC 경로는 고정 장애물로 계산해 정상적으로 양우리까지 연결한다.
- 이동할 때 경로에 플레이어가 있으면 그 칸 직전까지만 걷고 원래 남은 경로를 보존한다.
- 플레이어가 비키면 같은 경로로 즉시 이어 걷는다. 통과하거나 순간이동하지 않는다.
- 대기 중에는 전역 길찾기를 하지 않는다. 이전 0.5초 타이머와 `routeRetry` 필드는 제거했다.
- 플레이어를 피해 새 경로를 만들려고 모든 문을 찾는 조건 자체가 사라진다. 가구나 정식 목표가 바뀔 때의 경로 갱신, 정상 문 출입은 유지한다.

## 확인
- 같은 30개 시나리오(날씨2 × 시각5 × 위치3, 각40틱)의 실제 실패 경로가 수정 전20건에서 수정 후0건으로 줄었다. 시각은06:39/09:00/12:00/17:59/19:59다.
- 회귀 검사: 맑은 날·비 오는 날 실제 출근 시점의 입구/안쪽/바깥 점유에서 실패 경로0건.
- 회귀 검사: 입구 앞 대기300틱 동안 새 전역 길찾기0회. 플레이어가 비키면 다음 틱에 이동하며 목표에 도착한다.
- 기존 NPC 출입·동행·공동 주택·지도 위치 경로 검사 통과.
- 별도 렌더러 JS 비용 검사는 네 위치의 맑음·비 조건 모두 평균 약0.9~1.3ms 수준이었다. 가짜 캔버스 문맥이므로 실제 GPU 비용·FPS 결과가 아니다.
- TypeScript·콘텐츠 검사·Vite/PWA 빌드 확인. 브라우저는 기존 접근 거부 상태여서 사용자 기기의 실제 화면에서 렉이 사라졌다는 육안 확인은 하지 못했다.
