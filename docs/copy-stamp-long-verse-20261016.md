# 긴 절 필사 완료 표시 점검

2026-10-16 사용자: 짧은 줄은 괜찮지만 긴 줄을 필사하고 도장이 찍힐 때 표시 이상이 있다.

기존 완료 표시는 다음 절의 레이아웃 위에 완료 절 전체를 절대 배치하고, 도장을 본문 텍스트 뒤 inline 요소로 넣었다. 긴 절에서는 다음 절로 바뀌며 본문 스크롤이 0으로 돌아가고, 도장이 새 줄을 만들어 원래 쓰던 본문과 다른 높이로 표시될 수 있었다. 키보드 모드에서는 기존 최소 높이 고정도 CSS에 의해 무시됐다.

수정:
- 수기·음성·퍼즐 완료 전에 보던 칸 높이, 스크롤, 본문 시작 위치를 캡처한다.
- 완료 표시는 그 크기의 잘린 뷰포트로만 복제해 스크롤된 마지막 부분의 위치를 유지한다.
- 도장을 텍스트 흐름 밖으로 분리해 긴 절의 줄바꿈과 입력칸 높이를 바꾸지 않는다.
- 다음 본문은 완료 표시가 사라진 뒤 드러난다. 완료 효과가 끝나면 고정 높이를 해제한다.
- 본문·필사 판정·저장·보상·소요 시간은 변경하지 않는다.

검증: 긴/짧은 절, 스크롤 0/240px 및 완료 후 높이 해제 회귀 검사 추가. 손맛·키보드·음성·퍼즐·가구 방향 관련 55개 검사 통과 후, 마지막 변경에 대해 손맛·키보드 검사를 다시 통과했다. TypeScript, 전체 콘텐츠 검증, Vite/PWA 빌드 통과. 기존 브라우저 접근 정책 차단 때문에 실제 브라우저 시각 확인은 하지 못했다.

별도 책상 요청: 새 게임 기본 homeDesk가 원래 자리에서 오른쪽→위→왼쪽→아래로 돌아가는 회귀 검사는 통과했다. 사용자가 받은 보상 책상의 정확한 이름을 질문했고 답변 대기 중이다. 원인이 확인되지 않은 다른 가구의 동작이나 보상은 변경하지 않았다.


## 첫 장 보상 가구 후속 확인

사용자가 직접 추적을 요청하여 `writeVerse` → `applyEarlyGrowth` 경로를 확인했다. 첫 장 고정 보상은 `stool`(화면 이름 작은 의자)이며, 별도의 `chapterGift` 무작위 생활 가구와 구분된다. 원인은 `HOME_SPACE_DIRECTIONS.stool`이 `symmetric`로 네 방향 모두 같은 객체를 반환한 것이었다. 앞모습은 유지하고 뒤의 가로 받침과 좌우 측면 다리를 따로 그려 네 그림이 실제로 다르게 나오게 했다. 가구 ID·크기·보상 수·저장 형식은 바꾸지 않았다.

실제 첫 장 완료 → 보상 수령 → 설치 → UI 회전 단추 네 번 → 각 방향 저장/불러오기 검사를 추가했다. 방향 그림·배치·성장 보상 검사 총 28개 통과. 오프라인 원본 도트 시트 `artifacts/scenery/first-chapter-stool-directions.png`를 육안 확인했다. TypeScript·콘텐츠 verify·Vite/PWA 빌드 통과. 브라우저 직접 확인은 기존 권한 제한 때문에 수행하지 못했으며, 도트 시트 확인과 UI 자동 검사를 구분한다. 앞의 책상 이름 질문은 이 추적으로 해소되어 추가 답변이 필요 없다.
