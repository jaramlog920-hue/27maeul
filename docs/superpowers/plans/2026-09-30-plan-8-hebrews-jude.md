# 스물일곱 권의 마을 — 계획 8: 히브리서–유다서 방

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 서고의 셋째 잠긴 문(오른쪽 위, "히브리서–유다서 방")을 연다. 히브리서부터 유다서까지 여덟 권(히 13 · 약 5 · 벧전 5 · 벧후 3 · 요일 5 · 요이 1 · 요삼 1 · 유 1 = **34장**)을 계획 7과 **같은 흐름**으로 엮는다 — 편지 나르는 이웃이 장째로 하루 2–3통(한 장짜리 요이·요삼·유는 한 통에 통째로), 집 책상에서 빈칸 채워 옮겨 적기, 다 적은 책은 이 방 선반에 꽂고 편지 서고 퀴즈. 새로 정하는 것은 셋이다: ① 첫머리에 보낸 이 이름이 없는 편지(히브리서·요한일서, 그리고 직함 "장로"만 있는 요한이서·요한삼서)의 **"적혀 있지 않음" 문제 모양** ② 야고보·유다 같은 이름을 **본문 낱말로만** 적기 ③ 편지 서고 퀴즈의 빈칸 보기를 옮겨 적기와 같은 방식으로 골라 **끝말로 답이 드러나지 않게**.

**Architecture:** 계획 7이 끼울 자리를 이미 만들어 두었다 — 방 표 `SHELF_ROOMS`의 `hebJud` 줄(`mode: 'letters'`, `door: 2`)에 책 여덟을 넣으면 책 고르기·편지 나르기·옮겨 적기·방 열림(로마서–빌레몬서 방 열세 권이 모두 꽂힌 날 밤 → 다음 날 아침)이 그대로 돈다. 사람이 적는 콘텐츠는 첫머리 줄(`scripts/letters/opening.txt`)뿐이다. 퀴즈에는 새 문제 `openingNone`(보낸 이가 적혀 있지 않은 편지)을 더하고, 편지 책의 빈칸 문제를 `copy.ts`의 보기 고르기(끝말 같은 것 먼저·본문 어느 책에도 없는 문장)로 바꾼다 — 보기 고르기는 새 파일 `src/engine/word-options.ts`로 옮겨 `copy.ts`와 `quiz.ts`가 함께 쓴다(서로 import하는 고리 없이). 방은 서고 오른쪽 위 문 뒤 — 지도 아래 빈자리가 없으므로 `HEIGHT`를 70 → 80으로 늘리고 로마서–빌레몬서 방 바로 아래(30열, 70줄)에 짓는다. 오른쪽 벽 문은 열린 문 그림 `J`를 좌우로 뒤집어 그린다.

**Tech Stack:** 기존과 같음.

## Global Constraints

- **사용자 결정(2026-09-30, 설계 §7-2)** 그대로: 방 이름은 책 범위("히브리서–유다서 방"), "공동 서신"·"일반 서신" 같은 분류 이름은 화면 어디에도 쓰지 않는다. 편지는 장째로, 편지 나르는 이웃만. 기록 = 빈칸 옮겨 적기. 방 놀이판 없음. 탐정·도장 없음. 방은 앞 방(로마서–빌레몬서 방)이 다 찬 다음 날부터.
- **성경 콘텐츠 오류 0**:
  - 편지 본문은 `nt-krv.json`(개역한글)에서 장째로. 빈칸을 모두 맞게 채운 글은 원문과 한 글자도 다르지 않다(34장 전부 테스트). `(없음)`·`(…절에 포함되어 있음)` 절은 어디에도 보이지 않는다 — 여덟 권에 몇 개 있는지는 작업 1에서 **원문으로 세어** 테스트에 박는다(없으면 0으로 박는다). 괄호가 든 절·괄호 구간은 빈칸·퀴즈로 묻지 않는다(`quizzable`).
  - 첫머리 이름은 그 구절 본문에 **글자 그대로**(verify-letters). "누가 썼나요?"로 묻지 않는다. **저작 논쟁·전승 이름을 쓰지 않는다** — 히브리서·요한일서의 보낸 이를 짐작해 채우지 않고, 요한이서·요한삼서의 "장로"가 누구인지, 야고보서·유다서의 야고보·유다가 복음서·사도행전의 같은 이름과 같은 사람인지 화면·문서 어디에서도 말하지 않는다(exclusion §4-6). 책 이름(요한일서 등)에 든 사람 이름은 책 이름일 뿐 첫머리 줄의 근거가 아니다.
  - 모든 퀴즈 문장은 출제 범위(서고에 꽂힌 책 + 지금 책)에서 글자 그대로 한 곳에만(exclusion §4-1).
- 서고에 꽂힌 편지는 `shelvedCount`에 세지 않는다(계획 7과 같음).
- 옛 저장이 그대로 열린다: `progress`에 여덟 권 칸이 생기고, 방이 열리기 전에는 여덟 권이 책 고르기·도감에 보이지 않는다. 지도 높이가 늘어도 옛 저장의 자리(`player`·`companion`)는 그대로 쓸 수 있어야 한다(작업 5 테스트).
- 문구는 모두 `life-text.json`(금지어 verify). 그림은 청소년 톤 차분한 파스텔, 2픽셀 이상 선, 창 좌우 대칭, 하트·유아틱한 장식 금지.
- 커밋 전 네 가지 검사(`npm run verify`, `npx tsc -b`, `npx vitest run`, `npm run build`), 커밋 끝줄 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, 브랜치 `plan-1-trial`. 배포는 작업 6에서만(https://27maeul.vercel.app, 사용자 사전 승인).
- 파일은 Read/Grep/Glob으로 읽고 Write/Edit로 쓴다(PowerShell `Get-Content`/`Set-Content`는 한글을 깨뜨린다). 커밋 메시지는 파일로 써서 `git commit -F`.
