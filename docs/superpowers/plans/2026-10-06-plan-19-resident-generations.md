# 계획 19 — 주민의 자율 가족과 다음 세대

작성: 2026-10-06
상태: 기획 완료 / 구현 시작 전
연결 계획: [계획 18 — 구약 서고와 두 번째 마을](2026-10-05-plan-18-old-testament-village.md)

## 1. 사용자 의도와 완성 목표

주민 전체가 플레이어의 개별 명령 없이 관계를 맺고, 결혼하고, 아이를 낳고, 자녀가 성장해 독립하는 마을을 만든다.
‘전체’는 모든 주민을 이 체계에 참여시키는 뜻이다. 모든 사람이 반드시 결혼하거나 출산하는 뜻은 아니다.
혼자 사는 주민·아이 없이 사는 부부·부모와 사는 성인 자녀도 자연스러운 생활로 유지한다.

플레이어는 누가 누구와 결혼할지 지시하는 관리자가 아니라 이웃이다.
주택·공동 마당·꿈터를 마련하고, 결혼식·첫 심부름·독립·개장에 참여하며 세대의 변화를 지켜본다.
구약 맵은 이 가족들이 새로운 집과 일터를 마련하고 기억을 이어가는 공간이 된다.

## 2. 핵심 재미

- 예전에 만나던 주민의 아이가 자라서 새로운 이웃이 된다.
- 주민 자녀마다 외형·취향·관심·진로가 달라진다.
- 부모와 함께한 실제 활동과 물건이 가족 기억으로 남는다.
- 플레이어가 만든 집과 마당이 새로운 가족의 생활을 받아들인다.
- 부모의 꿈터를 자녀가 이어받거나 다른 꿈으로 발전시킨다.
- 구약 맵이 건물 수를 늘리는 공간을 넘어 여러 가족의 역사로 채워진다.

출산 알림만 반복하거나 새로운 아이를 도감 항목으로만 만들지 않는다.
각 가족은 관계 형성 이후 최소 한 개의 고유 생활 사건과 자녀 성장 후 변화를 가진다.

## 3. 시뮬레이션 시간과 사건 처리

- 게임 안에서 흐른 날짜만 사용한다. 현실에서 며칠 접속하지 않았다고 가족이 여러 세대 바뀌지 않는다.
- 두 마을은 같은 날짜·시간을 공유하고, NPC 가족 진행도 공통으로 관리한다.
- 가족 상태 갱신은 하루 정산에서 한 번 처리한다. 같은 날의 잠자기·불러오기·맵 이동으로 중복 진행하지 않는다.
- 각 가족은 한 번에 하나의 큰 전환을 진행한다. 하루 안에 연애·결혼·출산·성장이 연속 발생하지 않는다.
- 추첨 결과와 예정 사건은 저장한다. 재접속으로 배우자·아이 외형·선물을 다시 뽑지 않는다.
- 시간 건너뛰기 때도 기간 제한과 인구 제한을 지킨다. 이전 사건의 결과를 보존하고 새 사건을 순서대로 처리한다.
- 관계 형성·결혼·출생·성장·독립의 최소 기간은 실제 플레이 속도를 검토한 뒤 정한다. 현 단계에서는 일수를 확정하지 않는다.

## 4. 주민 관계의 흐름

단계: 이웃 → 친한 사이 → 서로 호감을 확인함 → 연인 → 결혼 준비 → 부부.
모든 관계가 연인으로 진행하지 않는다. 친구 관계도 이후 일과·소모임·생활에 남는다.

관계가 쌓이는 근거:
- 실제로 같은 장소에서 만나는 일과
- 함께 참석한 소모임·행사·작업
- 취향과 생활 시간의 적합성
- 설정된 성격·기존 관계·서사 조건

새 관계는 양쪽이 모두 성인이며 서로 동의할 때만 진행한다.
기존 배우자가 있는 주민, 미성년자, 부모·자녀·형제자매·가까운 친족은 새 연애 후보에서 제외한다.
가족 계보를 저장하고 다음 세대에도 같은 검사 규칙을 적용한다. 이름이나 외형으로 친족 여부를 추측하지 않는다.
주민의 기존 가족 설정·연애 성향·이야기 조건을 조사한 뒤 후보를 확정한다.

## 5. 플레이어와 기존 이야기 보호

- 플레이어의 배우자와 약혼자는 다른 주민과 자동 결혼하지 않는다.
- 플레이어의 현재 연인/진행 중인 구애 상대는 자율 연애 후보에서 보호한다.
- 모든 잠재 연애 후보를 영구 동결하지 않는다. 현재 진행 중인 관계의 판정과 종료 후 유예 기간은 구현 전에 정한다.
- 진행 중인 주민 이야기의 장소·참여자·관계 조건이 깨지는 전환은 완료 또는 안전한 구간까지 보류한다.
- 기존 주민에게 자동으로 이름·성격·직업·꿈을 새로 부여하지 않는다.
- 플레이어 가족과 주민 가족은 같은 기반을 쓰더라도 제어 방식은 분리한다. 플레이어의 결혼·출산 선택을 자동 처리하지 않는다.
- 첫 버전은 자동 죽음·이혼·재혼을 포함하지 않는다. 기존 주민이 갑자기 사라지는 구조를 만들지 않는다.

## 6. 결혼 준비와 집

연인이 충분한 기간 관계를 이어가고 함께 살 수 있는 집이 있으면 결혼 준비를 시작한다.
플레이어가 돈이나 가구를 주지 않았다는 이유만으로 모든 결혼이 영구 정지하지 않도록 기존 주택의 공동 거주도 지원한다.
새 집이 없는 경우 동거 가능한 기존 집, 독립 대기, 새 주택 희망의 세 경로를 둔다.
집 부족 상태를 주민의 부탁으로 보여주되 긴급 기한이나 관계 하락으로 압박하지 않는다.

결혼 전 초대 소식을 남긴다. 플레이어가 참석하면 공동 기억, 불참하면 실제 발생 사실만 기록한다.
이미 다른 일정이 있는 날은 피하고 기존 약속·행사 시스템을 재사용한다.
다른 맵에 있어도 결혼은 진행될 수 있지만 그날의 소식과 결혼 후 대화가 남는다.
식에 참석하지 않은 플레이어에게 참석 보상·참여 기억을 지급하지 않는다.

## 7. 출산과 가족 규모

결혼 이후 충분한 시간과 가족의 희망·거주 여건이 갖춰지면 아이를 기다리는 단계로 진행한다.
모든 부부에게 출산을 강제하지 않는다. 인구 제한이나 대기 상태를 벌점·실패로 표시하지 않는다.
출생 전에 작은 준비 대화를 두고, 출생 뒤 실제 부모·집·날짜·아이 ID를 기록한다.

- 초기에는 가족별 자녀 수 상한과 마을 전체 인구 상한을 둔다. 정확한 수는 성능·지도 크기를 검토한 뒤 결정한다.
- 집의 침대 개수 같은 특정 가구를 출산의 점수 조건으로 만들지 않는다. 안전한 생활 공간 유무로 거주 가능 여부를 판단한다.
- 수용 인원 부족 시 새 전환을 대기시키고 기존 가족은 보존한다.
- 입주를 거절하거나 집을 철거했다고 출생한 아이가 삭제되지 않는다. 안전한 임시 거처로 이동한다.
- 아이의 이름은 중복 표시를 허용하되 안정적인 내부 ID를 쓴다. 금지어·길이 규칙은 기존 기준을 따른다.

입양은 별도 후속 제안이다. 첫 버전의 출산과 성장 구현에 포함됐다고 표시하지 않는다.

## 8. 자녀 성장과 개성

단계: 아기 → 어린이 → 청소년 → 성인.
각 단계마다 외형뿐 아니라 활동 범위·일과·대화·도움받는 방식이 달라진다.

외형은 부모의 선택 가능한 머리·피부·색상 등을 바탕으로 조합하되 두 부모의 완전한 복사로 만들지 않는다.
생성된 외형은 저장하고 걷기·표정·가구 사용에 기존 도트 시스템을 재사용한다.
머리·옷·장신구는 나이에 맞는 허용 목록을 적용한다. 부모의 도트를 단순 축소해서 모든 성장 단계를 대신하지 않는다.

취향과 관심은 타고난 작은 차이와 실제 생활 경험으로 발전한다.
부모 직업을 자동 상속하지 않는다. 직업 추천은 현재 자식 직업 시스템의 능력·관심 규칙을 재사용한다.
NPC 자녀는 자신의 관심에 따라 결정하고, 플레이어는 활동 초대·배움 공간 제공으로 영향을 줄 수 있다.
성장마다 첫 심부름·처음 배운 작업·작은 발표처럼 구별되는 사건을 제공한다.

## 9. 다음 세대의 독립과 직업

성인이 되면 부모 집에 머물기, 기존 마을에서 일하기, 구약 맵의 새 집으로 독립하기 중 생활 여건에 맞는 경로를 선택한다.
독립 예정자는 수첩과 주택 희망 목록에 나타난다. 집을 즉시 지어주지 않아도 관계가 나빠지지 않는다.
기존 필수 상점과 서비스를 유지하도록 출퇴근 또는 견습 과정을 먼저 지원한다.

직업 계승 흐름: 관심 발견 → 배움/견습 → 작은 작업 → 진로 결정 → 일터 마련 → 독립 후 생활.
부모의 꿈터를 이어받을 때에도 실제 배움과 본인의 선택이 있어야 한다.
첫 버전에서 부모는 계속 살아 있으므로 업무 분담과 공동 운영으로 표현한다.
사망·은퇴·상속·무한 세대는 별도 설계가 필요한 후속 범위로 남긴다.

## 10. 구약 맵과 연결

| 계획 18 공간 | 주민 가족의 이용 | 이어지는 이야기 |
|---|---|---|
| 입주 주택 | 신혼부부·독립한 주민 자녀의 거주 | 집들이·첫 공동 생활·이웃 관계 |
| 집 겸 일터 | 직업을 정한 다음 세대의 작업 | 첫 작업·첫 손님·배움과 재도전 |
| 주민의 꿈터 | 부모와 자녀의 공동 운영 또는 새 꿈 | 계승·변경·역할 분담 |
| 손님집 | 독립 전 체류·친척 방문·임시 거처 | 첫 마을 가족과 재회 |
| 공동 마당 | 가족 식사·아이 발표·결혼 행사 | 실제 참석자별 기억 |
| 기억 정원 | 결혼·출생·성장·독립의 기념물 | 여러 가족의 역사 |
| 구약 서고 | 방문·열람·함께 읽기 | 세대가 함께 남긴 읽기 기억 |

첫 마을에서도 관계·결혼·출산·성장을 지원한다. 신약 완필 이전에는 인구 수용 범위 안에서 진행한다.
구약 맵을 열면 새 주택과 일터가 선택지에 추가되지만 모든 가족을 강제 이주시켜 첫 마을을 비우지 않는다.
주민 가족·새 외부 입주민·플레이어 자녀는 같은 주택 정원과 인구 기준을 공유한다. 누구를 위해 집을 마련할지는 플레이어가 선택한다.

## 11. 성경 기록과 생활 이야기의 연결 기준

구약 본문과 가상의 주민 이야기는 구분한다.
출산·결혼·부유함을 하나님께 받은 보상이나 필사 성과로 판정하지 않는다.
키워드를 많이 모았다고 아이가 더 태어나거나 더 뛰어난 아이가 되는 시스템을 만들지 않는다.
자녀 없는 가족이나 혼자 사는 주민을 부족한 삶으로 취급하지 않는다.

연결은 주제와 기억에 둔다.
예시: 실제 가족과 서고를 방문해 함께 읽은 날을 기록하거나, 신실하심에 관한 개인 기록을 가족의 약속과 함께 전시한다.
구약 인물의 사연을 NPC 가정에 그대로 재연시키거나 모든 생활 사건을 특정 성경 구절의 직접 성취로 설명하지 않는다.
해설 기준은 계획 18의 내부 편집·검토 규칙을 따른다.

## 12. 플레이어에게 보여줄 정보

- 작은 근황: 이웃 두 사람이 가까워졌다, 결혼을 준비한다, 아이가 태어났다.
- 주민 수첩: 배우자·부모·자녀·사는 집·일터·최근 기억.
- 가족 관계 보기: 발견한 인물부터 계보를 펼친다. 아직 만나지 않은 자녀의 상세 정보를 미리 전부 노출하지 않는다.
- 주택 희망 목록: 신혼집·독립집·일터를 원하는 주민과 이유.
- 달력: 초대받은 결혼식·발표·집들이. 단순 성장 정산은 매번 일정 알림으로 만들지 않는다.
- 가족별 기억: 실제 사건의 날짜·참여자·물건과 후속 대화.

하루의 소식은 묶어서 보여주고, 팝업이 반복되어 필사를 방해하지 않게 한다.
거주 중인 모든 주민을 찾아볼 수 있지만 모든 인물을 항상 화면에 동시에 그릴 필요는 없다.

## 13. 자율 진행 설정 제안

기본안: 주민 자율 생활 켜기, 느린 성장, 게임 시간 기준.
관계·가족 전환을 멈추는 설정과 주요 변화 전에 알림받는 설정을 제공한다.
끄더라도 현재 가족·아이·기억은 삭제하지 않고 새 전환만 멈춘다.
다시 켜면 지나간 기간의 결혼·출산을 한꺼번에 처리하지 않는다.
인구 상한·전환 속도는 게임의 추천값을 기본으로 하고 세부 조절 노출 여부는 이후 결정한다.

## 14. 데이터와 저장 구조 제안

기존 고정 주민 ID와 생성된 주민 ID를 분리한다. 생성 인물을 기존 NPC의 배열 번호로 식별하지 않는다.
제안 데이터:
- 인물: 안정적 ID, 생성/고정 구분, 생애 단계, 성장 시작일, 외형, 성향, 관심, 직업, 거주/일터 ID.
- 관계: 인물 두 ID, 관계 단계, 실제 공동 활동 기록, 전환 예정/완료 상태.
- 가족: 가구 ID, 구성원, 부모/자녀 관계, 거주지, 가족 희망과 진행 사건.
- 사건: 유일 ID, 종류, 예정일, 참여자, 완료 여부, 알림/보상 처리 여부.
- 마을: 인구 수용량, 독립 대기, 방문자/입주민 예약, 하루 정산 완료일, 난수 상태.

부모·배우자 연결은 양쪽에서 일관되어야 한다. 존재하지 않는 인물 참조와 순환 부모 관계를 복구한다.
옛 저장에는 안전한 기본값을 제공하고 기존 플레이어 가족을 NPC 가족으로 중복 생성하지 않는다.
날짜를 알 수 없는 옛 가족 기억은 미상으로 유지한다.

## 15. 필요한 그림과 콘텐츠

2026-10-06 자산 묶음 작성: `assets/old-testament-generations/`. 원본·좌표·미리보기·연결 안내가 있다. 자세한 범위는 `docs/old-testament-generations-assets.md` 참고. 기능 구현 체크박스는 그대로 미완료다.

- 주민 자녀의 성장 단계별 몸체와 4방향 걷기·표정.
- 결혼·돌봄·가족 식사·심부름·발표·견습에 실제 필요한 동작.
- 주택과 직업별 일터의 기존 자산 재사용/추가 목록.
- 계보·가족 기억·주택 희망 화면의 작은 아이콘.
- 관계 형성·결혼 후·출생·성장·독립 대사와 가족별 고유 사건.

현재 결혼·아이·행사 도트를 먼저 대조한다. 자산 존재와 게임 연결 완료를 구분한다.
새 인물 대사는 성격·직업·가족 관계에 맞는 검수된 템플릿을 기반으로 구성하는 안을 우선한다.
매 대화마다 외부 AI가 필요하도록 만들지 않는다.

## 16. 구현 단계

모든 항목은 현재 구현 전이다. 기존 플레이어 가족 기능과 구분해 완료를 표시한다.

- [ ] 1. 고정 주민의 나이·가족·연애·이야기 조사 및 보호 규칙 표 작성.
- [ ] 2. 주민/관계/가구/계보 기반과 옛 저장 호환, 하루 정산·난수·사건 중복 방지 구현.
- [ ] 3. 자율 관계 형성 대표 두 사람과 실제 공동 일과 연결.
- [ ] 4. 결혼 준비·거주·초대·결혼 후 일과를 대표 가족으로 검증.
- [ ] 5. 출생·가족 규모 제한·아기 돌봄·소식·첫 기억 연결.
- [ ] 6. 아기부터 성인까지 성장·외형·취향·관심·실제 활동 구현.
- [ ] 7. 능력/관심 기반 진로·견습·독립·필수 서비스 유지 구현.
- [ ] 8. 계획 18의 두 맵 왕래·주택·꿈터·손님집과 연결.
- [ ] 9. 수첩·계보·주택 희망·달력·가족 기억과 자율 진행 설정 구현.
- [ ] 10. 참여 가능한 전체 주민으로 확장하고, 가족별 고유 사건 보강.
- [ ] 11. 장기간 시뮬레이션·저장 복구·모바일·인구/성능·콘텐츠 검증.

첫 제작 목표: 대표 주민 한 가족의 ‘관계 → 결혼 → 아이 출생’까지 실제로 이어지는 경험.
두 번째 목표: 아이 성장·견습·독립과 구약 맵 주거 연결.
최종 목표: 참여 가능한 전체 주민이 이 규칙으로 살아가고, 마을의 세대 변화가 안정적으로 유지되는 상태.
전체 기능을 임시 인물 한 가족의 성공만으로 완료 처리하지 않는다.

## 17. 확인해야 할 시나리오

- 플레이어 배우자/연인 보호, 미성년자/친족 제외, 기존 이야기가 진행 중인 주민의 전환 보류.
- 같은 날 중복 정산·재접속·시간 건너뛰기 뒤 사건과 선물 중복 없음.
- 양쪽 부모·아이·배우자 관계와 계보 일관성, 고유 인물 ID 충돌 없음.
- 새 집 없음·정원 초과·집 철거·이사 취소 때 가족 보존과 안전한 거주.
- 두 맵에서 NPC 중복 출현 없음, 출퇴근과 약속 충돌 없음.
- 구약 맵 미개방/개방 저장 모두 진행 가능, 첫 마을 서비스 유지.
- 플레이어 가족·기존 기록·도트 외형·직업·관계·추억 보존.
- 자율 진행 끄기/켜기 때 기존 가족 보존, 밀린 사건 폭주 없음.
- 장기간 진행에도 인구가 정원을 넘지 않으며 화면과 저장의 크기가 관리 가능.
- 결혼하지 않거나 자녀 없는 주민도 대화·꿈·활동을 계속 이용 가능.
- 관련 검사·콘텐츠 검증·빌드·PC/휴대폰 확인 후 사용자 요청 범위에서 커밋·배포.

## 18. 아직 결정할 항목

정확한 기간·가족별 자녀 상한·총 인구 정원·첫 대표 가족·독립 정원·생성 인물 이름 목록은 구현 조사 후 결정한다.
노화·사망·이혼·재혼·입양·무한 세대·사업 상속은 후속 범위이며 이번 첫 구현에 포함하지 않는다.
출생과 독립까지 먼저 안정화한 뒤, 원래 주민을 계속 만날 수 있는 방식과 세대 교체 방식 중 플레이어가 원하는 방향을 결정한다.
