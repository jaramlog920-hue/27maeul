## 1. 만들려는 경험

집 옆 텃밭은 작은 생활 농사에 맞게 4칸만 남긴다. 나머지 밭과 옆 공터, 최대 증축에도 남는 집 뒤·밭 뒤 공터는 유저가 가진 물건을 놓고, 옮기고, 돌리고, 다시 거둘 수 있는 하나의 개인 마당으로 쓴다.

기존 빗물 항아리·갈대 말리는 틀의 설치/이동/철거 경험을 확장한다. ‘찻방 완성’, ‘정원 등급’, ‘가구 점수’처럼 공간의 정답을 만들지 않는다. 의자 하나만 놓거나 아무것도 놓지 않아도 완성된 마당이다.

### 사용자와 합의된 방향

- 집 옆에 있는 밭·공터를 활용한다.
- 집 뒤와 밭 뒤의 빈 땅도 포함하되, 집 확장으로 건물이 차지하는 땅은 모든 집 단계에서 제외한다.
- 농사 칸은 총 4칸으로 줄인다.
- 남는 땅은 자유롭게 설치·철거하는 공간으로 둔다.
- 빗물 항아리·갈대 말리는 틀처럼 이미 가진 물건을 직접 배치한다.

### 이 문서의 추천 결정

- 남길 밭은 2×2 고정 배치. 1차 구현에서 밭 자체 이동은 지원하지 않는다.
- 마당 자체의 별도 구입비·확장 공사·추가 완필 해금은 두지 않는다. 배치할 물건의 기존 획득 조건은 유지한다.
- 장식과 생활 가구를 먼저 허용한다. 농장 자동화, 주민 초대 행사, 새 생산 시설은 별도 후속 기능이다.
- 유저는 직접 눌렀을 때만 가구를 사용한다. 유저 자율행동을 추가하지 않는다.

## 3. 공간 배치

### 밭

- 추천 영구 밭: `(11,4)`, `(12,4)`, `(11,5)`, `(12,5)`.
- 기존 12칸 중 집 쪽 2×2를 유지해 밭의 위치를 알아보기 쉽게 한다.
- 나머지 8칸은 새 게임에서 처음부터 잔디다.
- 기존 저장의 재배 중 작물이 있는 칸은 임시 밭으로 남긴다. 7절의 전환 규칙 적용.

### 자유 마당

- 집 오른쪽 공터·남은 밭·집 뒤·밭 뒤를 하나의 자유 마당으로 연결한다. 앞마당/뒷마당을 별도 구입하거나 모드로 나누지 않는다.
- 기존 오른쪽 후보 영역 x=10~17, y=3~8에 더해, 뒤쪽 후보 띠 x=1~17, y=1~2를 함께 검토한다. 집 뒤와 오른쪽 사이 연결부 중 최대 증축에도 비어 있는 셀도 검토한다. 이 범위는 사진에서 확정한 외곽선이 아니라 지도 코드에 근거한 후보이다.
- 북쪽 지도 경계 y=0의 나무는 유지한다. 사진을 근거로 지도를 확장하거나 나무·집을 옮기지 않는다.
- 최종 범위는 사용자가 가리킨 집·밭 주변 공터로 한정한다. 서고나 다른 주민 땅까지 설치 영역을 넓히지 않는다.
- 집 앞 기존 도구 자리와 마당까지 접근하는 연결부도 확인한다. 기존 도구의 유효 배치 자리는 일괄 초기화하지 않는다.
- 최종 설치 영역은 하나의 명시적인 셀 목록/마스크로 관리한다. 거리 조건만으로 도로·이웃 땅까지 허용하지 않는다.
- 집 외형과 최대 증축 영역, 벽·지붕·나무, 고정 벤치, 문, 우편함과 편지 바구니, 큰길은 제외한다.
- 설치 가능 여부는 현재 집 단계만으로 판정하지 않는다. 최대 집 외형의 합집합을 처음부터 보호해 나중에 집을 확장해도 설치물이 쫓겨나지 않게 한다.
- 밭 4칸, 임시 밭, 반드시 필요한 접근 칸은 가구 설치에서 제외한다.
- 장식용 울타리를 강제 설치하지 않는다. 편집 중 경계 표시로 내 마당 범위를 알려준다.

### 설치 후에도 접근할 곳

집 출입구, 편지 바구니/우편함의 상호작용 자리, 밭 4칸과 임시 밭의 돌봄 자리, 활성화된 도구의 사용 자리, 마당에서 큰길로 나가는 연결점.

실내의 ‘모든 바닥 칸이 연결돼야 한다’ 규칙을 그대로 복사하지 않는다. 마당에서는 이 필수 접근점과 실제 사용 가구의 접근점이 도달 가능한지를 확인한다.

### 집 확장과 겹치지 않는 뒷공간

현재 `world.ts`의 외형 좌표는 다음과 같다.

| 집 부분 | 차지하는 좌표 |
|---|---|
| 본채 | x=3~7, y=4~7 |
| 배우자방 증축 | x=4~6, y=3~4 |
| 아이방 증축 | x=8~9, y=4~7 |
| 생활방 증축 | x=1~3, y=3~7 |

이 합집합과 실제 지붕 표현을 기준으로 안전한 뒷공간을 고른다. 예를 들어 뒤쪽 y=1~2 띠는 위 건물 좌표와 겹치지 않지만, 지붕에 가리는 정도·경계 나무·진입 동선·큰 가구 크기를 실제 화면에서 확인해야 한다.

- 집 단계 0~3에서 동일한 마당 소유/설치 셀 마스크를 사용한다.
- ‘지금은 빈 땅이니 설치 가능, 증축 후 자동 철거’ 방식은 사용하지 않는다.
- 뒤쪽 좁은 공간은 화분·등·작은 의자처럼 크기에 맞는 물건을 놓을 수 있다. 가구가 전체 점유 셀과 접근점을 확보하지 못하면 설치할 수 없다.
- 집 오른쪽 통로를 지나 뒷마당에 드나들 수 있어야 한다. 뒷공간에 들어간 유저/주민이 가구 설치로 갇히지 않는지도 확인한다.

## 4. 유저 조작

1. 집 근처에서 기존 꾸미기 진입 방식에 맞춰 ‘마당 꾸미기’를 연다. 야외에서는 마당 편집으로, 실내에서는 방 편집으로 문맥을 구분한다.
2. 가진 물건 중 야외 설치가 허용된 것만 목록에 표시한다.
3. 물건을 고르면 실제 크기·방향의 반투명 그림을 표시한다. 놓을 수 있는 자리는 초록색, 불가한 자리는 붉은색으로 표시한다.
4. 위치를 확정하면 가방에서 해당 수량만 사용한다. 취소하면 물건과 저장 상태를 바꾸지 않는다.
5. 이미 놓인 물건을 편집 중 누르면 ‘옮기기 / 돌리기 / 거두기’를 제공한다. 방향 그림이 없는 물건은 돌리기를 표시하지 않는다.
6. 편집을 끝내면 곧바로 평소 마을 화면으로 돌아간다.

### 짧은 안내 문구

- ‘내 마당에 놓을 자리를 골라 주세요.’
- ‘밭에는 놓을 수 없어요.’
- ‘집으로 가는 길을 남겨 주세요.’
- ‘이쪽으로 사용할 자리가 필요해요.’
- ‘가방에 빈칸이 필요해요.’

실패 원인은 현재 시도와 관련된 한 가지를 우선 보여준다. 긴 도움말·반복 경고·별도 보상창은 넣지 않는다.

### 철거와 이동의 구분

- 옮기기: 같은 배치 인스턴스의 좌표만 변경. 가방 공간이 필요하지 않다.
- 돌리기: 방향과 회전 후 점유 영역을 함께 검사. 실패하면 기존 방향 유지.
- 거두기: 가방 수용을 먼저 확인한 뒤 배치를 제거하고 물건 한 개를 돌려준다. 가방이 가득 차면 아무 상태도 바꾸지 않는다.
- 이동 중 취소·창 닫기·다른 저장 불러오기: 원래 위치와 소유 수량 유지.
- 편집 중에는 시간·유저·주민 진행을 기존 꾸미기와 같은 방식으로 멈춘다. 비활성 탭에서도 편집 동작이 자동 확정되지 않는다.

## 5. 설치 물건과 사용 범위

### 1차 허용안

기존 빗물 항아리·갈대 말리는 틀과 함께, 기존 물건 중 야외에서 자연스러운 것을 명시적으로 등록한다.

| 부류 | 후보 | 동작 |
|---|---|---|
| 기존 생활 도구 | 빗물 항아리, 갈대 말리는 틀 | 현재 생산·회수 규칙 그대로 |
| 앉는 가구 | 작은 의자, 의자, 긴 벤치 | 유저가 눌러 앉기. 실제 방향·앉는 위치 사용 |
| 탁자 | 탁자 | 우선 배치·작은 소품 올리기. 야외 차 마시기는 접근점과 실제 모션 연결을 검증한 뒤 허용 |
| 식물·소품 | 화분, 큰 화분, 꽃병, 바구니 | 기존 도트로 장식. 별도 생산이나 성장 효과 없음 |
| 바닥 장식 | 돗자리, 방석 | 밟고 지나갈 수 있음. 실제 사용이 연결된 항목만 사용 메뉴 제공 |
| 조명 | 등·랜턴 계열 | 기존 점등 표현과 호환되는 항목만 허용. 새 연료 소모는 추가하지 않음 |

후보 이름만으로 전부 허용하지 않는다. 실제 `ItemId`, 도트 크기, 방향, 모션, 설치 가능 층을 대조한 뒤 허용 목록을 확정한다. 울타리처럼 현재 가방 물건으로 확인하지 않은 항목은 자동 포함하지 않는다.

### 1차 제외

벽걸이, 고정 침대·화덕·필사 책상, 서고 설비, 주민 소유 가구, 집 증축 구조물, 새 터 건물. 야외 전용 벽 시스템이나 비·눈에 의한 가구 손상도 만들지 않는다.

### 가구 동작

- 네 방향 도트가 있는 물건은 설치·회전·상호작용 모두 같은 방향을 사용한다.
- 앉는 방향과 접근 칸이 실제 의자/벤치 방향에 맞아야 한다.
- 쓰는 사람이 있는 가구는 이동·회전·회수 전에 사용과 예약을 안전하게 종료한다.
- 얼굴·짧은 팔·손·발이 가구와 어긋나거나 가려지지 않도록 기존 캐릭터 기준으로 확인한다.
- 장식 전용 물건에는 동작하지 않는 ‘사용’ 단추를 만들지 않는다.
- 식탁 배치만으로 식사 인원·요리 수량·상호작용 기능을 자동 부여하지 않는다. 기존 요리/식탁 엔진의 허용 조건을 별도로 연결한다.

### 주민·가족·반려동물

- 유저의 자동 착석·자동 행동은 없다.
- 주민/자녀의 자율 사용은 기존 해금·설정·나이·일정 조건을 만족하는 경우에만 확장한다. 마당 설치가 자율생활 해금을 대신하지 않는다.
- 주민이 원래 하던 일을 취소하고 마당으로 강제 이동하지 않게 한다. 초기 범위는 마당을 실제로 지나거나 방문한 인물의 짧은 사용이다.
- 유저 조작과 다른 사용자의 예약이 충돌하면 한 가구에 겹쳐 앉지 않도록 한다.
- 고양이는 계속 실내 생활. 강아지의 기존 따라오기/집에 두기 선택과 유저 통과 규칙도 유지한다.
- 반려동물 가구의 야외 사용은 동물별 이동 범위와 사용 모션을 검증한 후 후속 허용한다. 설치 가능과 실제 사용 가능을 구분한다.

## 6. 아키텍처

### 단일 설치 상태와 기존 도구 어댑터

일반 야외 가구를 `game.room`에 넣지 않는다. 실내 방 판정·가구 정리·동선·반려동물 쉼터 코드가 잘못 읽을 수 있기 때문이다.

추천 신규 상태:

```ts
interface OutdoorPlacement {
  id: string;             // 같은 물건을 여러 개 놓아도 각각 식별
  item: ItemId;
  x: number;
  y: number;
  facing: Facing;
}

interface OutdoorState {
  version: 1;
  placements: OutdoorPlacement[];
}

// GameState에 optional로 추가. 없는 옛 저장은 최초 마이그레이션.
outdoor?: OutdoorState;
```

- `outdoor.placements`를 설치 상태의 단일 원본으로 삼는다.
- 기존 `yard` 좌표와 `yardOff:*`, `unlock:*`는 마이그레이션 입력 및 기존 도구 소유/해금 규칙으로 해석한다.
- `yardSpot`, `yardPlaced`, `yardItemAt`, `moveYard`, `stowYard` 호출은 어댑터로 새 원본에 연결해 생산 코드와 기존 조작을 단계적으로 보존한다.
- 새 상태가 생긴 뒤에는 옛 `yard` 좌표를 별도 설치물처럼 다시 렌더하거나 복원하지 않는다.
- 기존 도구는 현재처럼 종류별 한 개라는 규칙을 유지한다. 일반 가구는 실제 가진 수량만큼 여러 개 허용한다.
- 도구 첫 획득은 기존 자동 설치 의미를 보존하도록 구매/해금 경로에서 한 번 처리한다. 이후 사용자가 거둔 물건을 불러오기에서 임의로 다시 설치하지 않는다.
- 설치 상태와 가방 수량 변경은 하나의 성공 결과로 반환한다. 저장 실패 시 기존 저장 실패 안내를 쓰며 무한 재지급하지 않는다.

### 추천 모듈 경계

### 배치 검사 순서

허용 물건 → 보유 수량 → 회전된 전체 점유 셀 → 설치 경계/밭/고정물 → 같은 층 겹침·탁자 위 소품 관계 → 필수 접근점 연결 → 사용 접근점 → 성공 결과.

- 길찾기에는 기존 지도·잠긴 구역·이야기 소품과 함께 야외 가구 차단을 합친다.
- 유저와 NPC가 서로 다른 야외 가구 차단 목록을 쓰지 않도록 공통 조회 함수를 둔다.
- 최대 집 증축 영역과의 교차 검사는 `HOUSE_RECT`·`HOME_EXTERIOR_ADDITIONS`에서 공통으로 계산한다. UI와 저장 검증에 따로 좌표를 복사하지 않는다.
- 장식·바닥 깔개는 기존 층 규칙을 따른다. 기존 도구는 계속 통행 비차단이다.
- 탁자 회수·이동 시 위의 작은 소품을 버리거나 복제하지 않는다. 1차에서는 소품이 올려진 탁자는 소품을 먼저 거두도록 짧게 안내하는 방식을 추천한다.
- 유저·주민이 서 있는 칸을 막는 배치는 허용하지 않는다. 편집 종료 후 경로/사용 예약은 변경된 배치에 맞게 무효화한다.
- 경로 검사는 배치가 바뀌는 시점에 실행한다. 매 렌더 프레임마다 전체 마당 경로를 다시 탐색하지 않는다.

## 7. 기존 저장의 무손실 전환

### 기존 12칸 작물

1. 기존 원본 12칸의 작물을 새 4칸 목록으로 정리하기 전에 읽는다.
2. 영구 밭 4칸의 작물은 그대로 둔다.
3. 나머지 8칸에 심긴 작물은 원래 좌표·작물·성장량·물준 날을 유지해 `gardenTransition` 같은 명시적 임시 밭 기록으로 보존한다.
4. 임시 밭에서는 기존대로 물주기·성장·수확이 가능하다. 새 씨앗은 심을 수 없다.
5. 수확 보관 공간이 부족하면 기존 수확 실패 규칙대로 작물과 임시 밭을 그대로 둔다.
6. 수확이 성공하면 해당 임시 밭만 제거하고 잔디로 전환한다. 그때부터 가구를 놓을 수 있다.
7. 임시 밭이 모두 없어지면 전환 기록을 비운다. 이후에도 정상 저장으로 인식한다.

`moveGardenPlots`에 4칸 배열만 전달하는 구현은 금지한다. 현재 함수는 넘치는 작물을 버리므로 이 전환을 먼저 처리하도록 순서를 바꿔야 한다.

원래 12칸 밖 좌표를 가진 더 오래된 저장도 자동 삭제하지 않는다. 기존 보정으로 수용할 자리가 없으면 별도 복원 대기 기록에 보존하고 안전한 칸에 순차 복원하는 정책을 둔다. 무한 복제나 수확 선지급으로 보상하지 않는다.

### 기존 빗물 항아리·갈대 말리는 틀

- 설치 중이면 원래 좌표를 우선 보존한다. 기존에 가방에 있던 물건을 다시 차감하지 않는다.
- 거둔 상태면 가방과 거둠 표식을 유지한다. 설치 목록에 새 물건을 만들지 않는다.
- 유효한 옛 배치는 새 경계 때문에 갑자기 철거하지 않는다. 옛 자리에서 계속 쓰게 하되, 새 위치를 고를 때는 새 설치 범위를 안내한다.
- 임시 밭·고정물과 겹치는 비정상 배치는 물건을 삭제하지 않고 복원 대기 상태로 보존한다.
- 도구 해금만 되고 아직 새 상태로 변환하지 않은 저장과, 사용자가 의도적으로 거둔 저장을 구분한다.
- 마이그레이션 버전으로 반복 불러오기 시 설치물·가방 물건·생산량이 중복되지 않도록 한다.

### 기타 호환

다른 저장 칸, 기존 집 안 가구, 농사 수확량·성장 일수, 기존 닢·재료·호감도·완필·해금·도구 일일 생산량을 변경하지 않는다. 4칸 축소는 재배 면적만 줄이는 변경이며 씨앗 가격이나 작물 수확량을 동시에 바꾸지 않는다.

## 8. 렌더링·표현

- 기존 가구 원본을 공통으로 사용한다. 야외용 색칠 복제본이나 화면 확대/축소로 크기를 맞추지 않는다.
- 지면 → 바닥 장식 → 가구와 인물의 앞뒤 정렬 → 손·소품 등 기존 사용 모션 레이어 순서를 문맥에 맞게 유지한다.
- 전후 방향과 회전 후 가로/세로 크기가 선택 미리보기·실제 지도·상호작용에서 일치해야 한다.
- 밤·비·눈에는 기존 지도 조명을 따르되, 물건이 사라지거나 회수되는 효과는 없다.
- 기본 캐릭터와 실제 저장 외형, 큰 머리·모자·의상에서도 얼굴과 손이 가려지지 않는지 확인한다.
- 마당 전체를 새 장면이나 별도 지도 화면으로 전환하지 않는다. 기존 마을에서 계속 보이고 오갈 수 있다.
- 집 뒤의 가구는 실제 앞뒤 순서에 따라 지붕 뒤로 일부 가려질 수 있다. 가구를 무조건 지붕 위에 그리지 않는다. 편집 중에는 선택 윤곽·점유 표시로 위치를 확인할 수 있게 하고, 실제 사용할 인물과 물건이 과도하게 가려지는 배치는 별도로 시각 검증한다.
- 이벤트 배경이 실제 집 주변 설치물을 보여주는 경우 같은 설치 상태를 읽는다. 미리보기·썸네일에서 게임 저장이나 앨범을 수정하지 않는다.

## 9. 구현 순서와 검증

### A. 기반과 저장 전환

- 지도 대조 후 마당 설치 마스크와 밭 4칸 확정.
- 작물 전환부터 구현하고 저장 왕복 검증.
- 야외 설치 상태와 기존 도구 어댑터 연결.
- 이 단계에서 일반 가구를 열기 전 기존 도구 생산·설치·철거가 동일하게 동작하는지 확인.

### B. 자유 배치

- 1차 허용 가구의 실제 ID·크기·방향 목록 확정.
- 설치·이동·회전·거두기와 미리보기·재고 처리 연결.
- 통행·큰길 연결·밭과 도구 접근점 검사.

### C. 사용과 표현

- 직접 앉기부터 연결. 탁자/소품/차 동작은 실제 사용 가능한 항목만 순차 허용.
- 기존 자율생활 조건을 지키는 주민·자녀의 가구 사용을 연결.
- 모션을 연결하지 않은 물건은 장식으로만 표시.
- 최종 화면 확인과 관련 검사·빌드 후 배포.

### 필수 검사 목록

- 새 게임: 정확히 4칸만 심을 수 있고 나머지는 잔디/마당.
- 집 단계 0·1·2·3: 집 뒤·밭 뒤 설치 영역이 증축과 겹치지 않으며 설치물이 유지됨. 현재 빈 증축 예정 칸에도 잘못 설치되지 않음.
- 뒷마당: 경계 나무를 침범하지 않고 진입/탈출 가능. 좁은 띠를 가구로 막거나 회전할 때 사용자가 갇히지 않음. 지붕 가림과 편집 선택 표시를 실제 화면에서 확인.
- 기존 저장: 12칸 모두 재배 중이어도 작물·성장·물주기 상태가 하나도 사라지지 않음.
- 임시 밭: 새 심기 불가, 물주기/성장 정상, 수확 실패 시 보존, 성공 후 그 칸만 잔디 전환.
- 반복 저장·불러오기 및 다른 저장 칸: 작물·도구·가구 복제나 칸 간 오염 없음.
- 도구: 위치와 설치 상태 보존, 거두면 생산 중단, 다시 놓으면 기존 규칙대로만 생산.
- 가구: 재고 한 개씩 처리, 이동/취소 무차감, 가방이 찬 회수 실패, 여러 개 배치의 개별 식별.
- 회전: 네 방향 그림·점유·발 위치·접근 칸 일치. 지원하지 않는 방향 버튼 없음.
- 통행: 출입문/우편함/길/밭 접근 유지. 주민이 막힌 경로를 매 틱 반복 탐색하지 않음.
- 상호작용: 편집과 사용 입력 충돌 없음. 탁자 위 물건 소실 없음. 사용 중 회수/저장 변경 시 예약 정리.
- 자율생활 해금 전/후·설정 끔·유저 정지: 기존 조건 유지, 유저 자율행동 없음.
- 고양이 실내 유지, 강아지 기존 이동/통과 유지.
- 실제 브라우저에서 PC·모바일 터치, 배치/이동/회전/회수/사용/저장 재접속을 시각 확인.
- 관련 엔진·저장·방향·사용 모션·UI 검사와 전체 빌드 통과.

## 10. 완료 기준

유저가 별도 공사 없이 집 옆·집 뒤·밭 뒤의 지정 공터를 하나의 마당으로 꾸미고, 이미 가진 도구와 가구를 직접 옮기고 거둘 수 있다. 집을 최대로 증축해도 설치 영역과 물건이 유지된다. 밭은 새 심기 기준 4칸이며 기존 작물은 수확까지 보존된다. 생활 동선과 기존 보상·생산·저장 상태가 유지되고, 실제 사용할 수 있는 가구만 동작 메뉴를 제공한다.

테마 판정·수집 보상·새로운 숙제 없이, 마을을 걸을 때 늘 보이는 ‘내가 꾸민 마당’이 되는 것을 목표로 한다.

## 11. 1차 구현 기록 — 2026-10-19

- 영구 밭을 `(11,4)`, `(12,4)`, `(11,5)`, `(12,5)` 네 칸으로 변경했다.
- 마당 범위는 x=1~17, y=1~8 중 실제 바깥 지면으로 확정했다. 본채와 모든 증축 부지를 공통 정의에서 제외하며 경계 나무·고정물을 보호한다.
- 기존 작물은 별도 복사/이동 없이 `garden`의 원래 좌표에 보존한다. 새 심기만 네 칸으로 제한하므로 기존 초과 작물은 물주기·성장·수확 후 자연스럽게 잔디로 전환된다. 기존 저장 보정 함수의 초과 작물 삭제를 없앴다.
- 일반 마당 가구는 `outdoor: {version:1, nextId, placements}`에 개별 ID로 저장한다. 실내 `room`·새 터 `rooms`와 분리했다.
