# 서고 성장 개편: 2차 구현

## 실제 연결한 기능

신약 누적 완료 장과 완필 권 수로 접근 권한을 계산한다. 책 선택 순서는 자유이며 구약은 성장 계산에서 제외한다. 기존 저장은 `growthLegacy`로 이전 이용 권한을 유지한다.

| 기능 | 체험 | 정식 이용 |
|---|---|---|
| 요리 | 15장: 허브 차, 기본 빵 | 4권 |
| 소모임 | 20장: 차 모임 하나 | 5권 |
| 좌판 | 없음 | 6권 |
| 공동시설 | 25장: 제안 하나 열람 | 7권: 건축 시작 |
| 여행 | 없음 | 8권: 출발, 돌아오기는 항상 허용 |
| 서고 관리인 지정 | 없음 | 10권 |
| 연애 시작·배우자 방·청혼 | 없음 | 각각 17·18·19권 |
| 아이 방·출생·학교 | 없음 | 각각 21·22·24권 |

완료 장 안내는 15·20·25장까지 확장했다. 체험과 정식 안내는 한 번만 발생한다. 이미 시작한 활동과 기존 아이의 생활은 계속 처리한다. 이동 구역과 주민 이사도 완필 권 수를 반영하되 이미 전시한 권으로 열린 구역을 다시 잠그지 않는다.

## 본문과 화면 로딩

- `scripts/build-nt-content.mjs`: 원본 본문과 길잡이를 신약 27권으로 묶고 작은 색인을 만든다. 원본 수정 후 `npm run build:nt`를 실행한다. 빌드 검증에서 원본과 생성물 일치를 검사한다.
- `nt-loader.ts`: 선택한 책만 불러오며 동시 요청을 합치고 실패하면 다시 요청할 수 있다. 완료 장 계산과 지도 표시는 본문을 받지 않는다.
- `NtContent.tsx`: 필요한 본문이 준비된 뒤 화면을 표시하고 실패·재시도를 안내한다. 로딩 중 창을 닫으면 늦게 도착한 요청이 필사 창을 다시 열지 않는다.
- 생활 화면 12개를 `React.lazy`로 분리했다. 공유 버튼·문구는 별도 모듈로 분리하여 정적 import가 큰 화면을 다시 포함하지 않도록 했다.
- 본문과 분리된 화면은 PWA 사전 캐시에서 제외하고 이용할 때 캐시한다. 아직 받지 않은 책·화면은 처음부터 오프라인에서 열 수 없다. 구약 기능의 기존 코드는 유지하며 이번 성장 개편에서는 제외했다.

## 확인 결과

- 관련 테스트 20개 파일, 418개 통과. 공유 모듈 분리 후 추가 확인한 화면 테스트 17개 통과.
- `npm run build`: TypeScript, 콘텐츠 검증, 배포 빌드 성공.
- `npm run measure:startup`: 정적 의존성을 포함한 첫 화면 JS 2개, 2,196.65 kB, gzip 660.23 kB. 본문과 생활 화면이 정적 의존성 및 PWA 사전 캐시에 없는 것을 확인한다.
- 1차 빌드의 메인 JS 3,350.14 kB 대비 약 34% 감소했다. 이 값은 JS 파일 크기이며 실제 기기의 로딩 시간 측정값은 아니다.
- 전체 테스트 통과를 의미하지 않는다. 기존 `game.test.ts`와 `ModalLayer.test.tsx`의 실패는 앞선 변경 전 상태에서도 재현했다.

## 남은 작업

이 단계에서 남았던 후반 해금 연결과 7장 시각 변화는 [3차 구현](library-growth-phase3.md)에서 진행했다. 후속 검증과 적용 범위는 해당 문서를 참고한다.

첫 로딩의 공통 게임 저장소·렌더링·콘텐츠 코드가 아직 커서 번들 크기 경고가 남는다. 추가 분리는 실제 파일 비중을 확인한 뒤 진행한다. 모바일 실기기에서 첫 실행, 느린 연결, 오프라인 재접속, 기존 저장 불러오기까지 확인하는 것도 남아 있다.
