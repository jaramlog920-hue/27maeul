# 브라우저 저장

진행 기록·저장 시각·현재 저장 칸·앨범 사진은 `twenty-seven-storage` IndexedDB의 `game` 저장소에 보관한다. 작은 기기 설정은 기존 localStorage에 둔다.

앱은 `StorageGate`에서 저장소를 연 뒤 시작한다. 첫 실행은 기존 localStorage의 게임 키를 하나의 트랜잭션으로 옮기고, 완료 표식을 같은 트랜잭션에 넣는다. 원본은 보존하며 이후 실행에서는 다시 가져오지 않으므로 삭제한 칸이 되살아나지 않는다. 열기나 이전에 실패하면 빈 게임으로 진행하지 않는다.

엔진은 초기화된 메모리 캐시를 동기적으로 읽는다. `saveGame`의 반환값은 저장 대기열에 넣었는지를 뜻한다. 완료 안내·새로고침은 `saveGameAsync` 또는 `flushGameStorage`가 실제 IndexedDB 트랜잭션 완료를 확인한 뒤 실행해야 한다. 가져오기·새 칸 복사·삭제는 원자적 작업이며, 실패한 작업은 캐시도 되돌린다. 여러 탭이 같은 키를 바꾸면 비교 후 충돌을 알리고 덮어쓰지 않는다.

내보내기 형식은 v2이며 예전 v1도 가져온다. 진행·해당 칸의 모든 사진을 함께 담고, 화면 크기를 포함한 기기 설정도 담는다. 다른 칸을 내보낼 때는 `exportSave(game, undefined, slot)`처럼 원본 칸을 명시한다. 가져오기에서 사진 일부만 누락한 상태를 성공으로 처리하지 않는다. 작은 설정을 적용하지 못하면 개수를 별도로 알린다.

공간 부족 등 비동기 저장 오류는 `StorageNotice`가 알린다. 실패한 최신 진행과 사진은 메모리에 남아 파일로 내보내거나 재시도할 수 있다. 사용자가 안내를 미루면 작은 재열기 버튼을 남긴다. 안내창이 열려 있는 동안 마을의 시간도 멈춘다. 브라우저 사이트 데이터를 지우는 해결책은 제시하지 않는다.

공간 부족 안내의 ‘오래된 저장 칸 정리’에서는 현재 칸을 제외한다. 다른 칸의 파일 받기, 실제 보관 확인, 삭제 확인을 거쳐야 지울 수 있다. 삭제 시 최신 현재 진행도 함께 저장하며, 공간 부족으로 밀린 저장이 있으면 삭제와 함께 원자적으로 처리한다.

검증 파일: `game-storage.test.ts`, `save-indexeddb.test.ts`, `StorageGate.test.tsx`, `StorageNotice.test.tsx`, `StorageCleanup.test.tsx`, `save-file-download.test.ts`. 실제 브라우저 검사는 `artifacts/storage-migration-check.cjs`이며, 기존 사용자 프로필과 분리된 임시 Edge 프로필과 로컬 개발 서버를 사용한다.
