27마을 — 직접 요리하고 함께 먹는 생활
작성일: 2026-10-05
상태: 추후 구현할 기획. 기존 빵 만들기·먹기·가족 저녁을 확장한다.

1. 목표와 완성 모습
집의 화덕과 준비 자리에서 음식을 만들고, 혼자 먹거나 가족·이웃과 나눈다.
재료를 고르고 손질하고 차리는 과정에 플레이어의 선택이 남는다.
같은 요리라도 모양·곁들임·함께 먹은 사람에 따라 생활 기억이 달라진다.
요리는 필사와 별개로 선택하는 활동이며 새 요리를 배우지 않아도 기존 음식으로 생활 가능.

완성 장면 예시
텃밭에서 얻은 콩을 가지고 집에 돌아온다. 화덕에서 콩 요리를 선택하고
물과 재료를 확인한 뒤 저어 만든다. 오늘은 허브를 곁들이기로 한다.
완성 음식은 가방에 넣거나 탁자에 차린다. 집에 있는 배우자는 자기 취향으로 반응한다.
아이도 실제 성장 단계에 맞춰 작은 역할을 고른다. 처음 함께 만든 날은 가족 앨범에 남는다.
요리 후 그릇을 정리하면 평소의 집 모습으로 돌아간다.

2. 현재 기능에서 유지할 것 — 코드 점검 기준
items.ts: bread/honey/fig/bean이 먹을 수 있는 물건이며 배고픔 감소 수치가 있음.
기존 빵 제조: barley 1 + water 1 → bread 2, 화덕, 게임 시간 30분, mash 미니게임.
기름 제조와 텃밭 herb/bean 구조도 있음.
family.ts: 가족 활동의 빵 결과와 배우자 저녁, 첫 저녁 앨범 기록이 이미 있음.
기존 재료 소비·제조 수량·먹기·가족 저녁·옛 저장을 보존.
새 요리 화면은 기존 제작법을 안내하고 확장한다. 별도 빵 아이템과 저녁 시스템을 중복 생성하지 않는다.
위 상태는 점검 당시 작업 폴더 기준이며 구현 전에 병행 작업 결과와 다시 대조.

3. 장소와 도구
화덕: 굽기·끓이기. 기존 필수 화덕을 이용해 기본 요리 시작 가능.
준비 자리: 기존 지원 탁자/작업대의 안전한 자리. 손질·반죽·차리기.
식사 자리: 09 집 안 공간의 탁자·앉을 자리. 함께 먹기와 초대 연결.
기본 그릇·주걱은 기본 요리에서 제공하는 사용 도구이며 매번 구매/소모하지 않는다.
장식 그릇·차받침·탁자 천은 외형 선택. 비싼 주방이 필수 조건이 아님.
기본 식사 자리가 없으면 혼자 먹기나 기존 가족 저녁 이용은 가능.
냉장고·가스레인지·전자레인지 등 현대 기기는 추가하지 않는다.

4. 첫 이용과 화면
기존 화덕 메뉴의 만들기에 음식 종류를 묶거나 ‘요리하기’로 연결.
음식 목록에는 완성 그림, 필요한 재료, 소요 시간, 결과 분량, 사용 장소 표시.
재료가 부족하면 부족한 것과 실제 얻는 방법을 보여 준다.
알지 못하는 제작법은 ‘이웃과 함께 배우기’에서 발견. 지원되지 않는 약속/빈 메뉴를 노출하지 않는다.
재료 확인 → 만들기 → 결과 → 먹기/차리기/보관 중 선택.
휴대폰은 단계별 한 화면, 작은 클릭 영역이나 계속 누르는 조작을 피한다.

5. 요리 플레이
준비: 주재료와 지원되는 곁들임 선택. 재료 소비는 시작 확정 때 한 번.
손질: 씻기/분류/반죽 중 요리에 맞는 짧은 한 동작.
조리: 젓기/굽기 중 짧은 한 동작. 기존 미니게임을 맞는 경우 재사용.
마무리: 모양·담는 방식·곁들임 선택. 준비 때 소비한 재료를 다시 빼지 않는다.
결과: 완성 음식 그림과 분량. 즉시 먹거나 가방/식탁으로 이동.
모든 요리에서 같은 3개 미니게임을 반복하지 않고 1~2개 참여와 선택으로 구성.
차분하게 만들기를 지원. 조작 속도로 결과를 크게 벌주지 않는다.

6. 첫 지원 메뉴 — 아래 새 메뉴의 수량/시간은 기획 기본값
기존 빵: 현재 barley+water 및 결과 bread 2를 그대로 유지.
꿀 곁들인 빵: bread 1+honey 1, 빵 한 접시 1개. 덧붙인 음식 ID를 실제 지원할 때 도입.
무화과 간식 접시: fig 1, 간식 한 접시 1개. 기존 fig를 그냥 먹는 선택도 유지.
콩 요리: bean 1+water 1, 한 그릇 1개, 화덕 약 30분.
허브 콩 요리: 콩 요리 또는 기본 조리 재료+herb 1. 같은 재료를 이중 소비하지 않는 경로 하나로 확정.
올리브 곁들임: olive 실제 획득과 먹기 지원을 확인한 뒤 추가. 생활용 oil을 식용으로 자동 취급하지 않는다.
허브 차: herb+water를 쓰는 생활 음료로 기획. 음식 포만 수치와 분리하고 약효를 붙이지 않는다.
그 외 생선·달걀·우유·밀가루 요리는 재료 생산/거래가 실제 준비된 뒤 추가. 현재 있다고 가정하지 않는다.
처음에는 기존 빵+새 요리 2~3종을 먼저 연결하고 완성형 메뉴는 플레이 확인 후 늘린다.
하나의 재료 단위에서 접시를 무한히 나누거나 원재료보다 수익이 과도하게 늘지 않도록 조정.

7. 선택과 결과의 차이
모양: 길쭉한 빵/둥근 빵 등 실제 지원하는 그림.
무늬: 가장자리/표면의 간단한 장식. 기존 빵 수량과 효능을 임의로 바꾸지 않는다.
곁들임: 꿀·과일·허브 중 레시피에서 허용된 선택과 실제 재료.
그릇과 천: 개인 취향을 보여 주는 꾸미기. 음식 효과 배율은 붙이지 않는다.
기본/응용 구분은 지원하는 모양과 재료 중심. 별점·등급·희귀도 경쟁을 핵심으로 하지 않는다.
음식 종류와 변형 ID를 분리하고 모든 색 선택마다 가방 아이템을 무한 생성하지 않는다.
가방에서 다른 재료/선택의 완성품을 합치는 기준을 사전에 정한다.

8. 함께 먹기
차린 뒤 실제 같은 장소에 있고 참석 가능한 인물을 초대.
기본 2~4명. 자리가 없거나 시간이 안 맞으면 가능한 대안 안내.
혼자/가족/이웃 식사 모두 가능. 혼인 여부로 기본 요리를 제한하지 않는다.
가족 저녁이 이미 발생한 날은 새 식사 회차와 소비/보상/기억을 중복 처리하지 않는다.
기존 가족 저녁을 소급해서 플레이어가 새로 만든 음식을 소비한 것으로 바꾸지 않는다.
음식 한 개는 한 끼 제공 단위. 인물별 사용량과 실제 분량을 시작 전에 안내.
NPC가 보탠 음식은 회차 공급분으로 관리하고 플레이어 가방으로 반복 지급하지 않는다.
참석하지 않은 사람은 공동 식사 기억에 넣지 않는다.
동물 음식은 별도 체계. 사람 음식이 모두 반려동물에게 적합하다고 가정하지 않는다.

9. 주민 취향과 배움
빵 굽는 이웃/웬델: 빵 모양·간식 진열·함께 맛보기.
파피: 찻잔·차·간식의 조합과 자기 취향.
바질: 허브 차와 생활 준비. 건강 효능은 단정하지 않는다.
메리골드/할아버지: 수확 바구니와 계절 재료 선택.
다른 주민도 좋아하는 맛·모양·식사 장소·함께하는 방식은 캐릭터 설정과 대조해 작성.
선물 취향을 음식 취향으로 그대로 복사하지 않는다.
맵거나 특정 재료를 못 먹는 등 새 설정은 최종 캐릭터 데이터에서 명시한 경우만 적용.
낯선 음식을 조용히 살피거나 다른 곁들임을 제안하는 반응. 싫어한다고 모욕/관계 급락 없음.
배움: 이웃 시범 → 안전한 실습 → 새 모양/제작법 → 실제 사용 후 대화.
반복 학습으로 제작법·재료·보상이 중복 지급되지 않게 함.

10. 아이와 가족
아이: 재료 이름 고르기·모양 정하기·안전한 반죽·접시 선택.
불·칼·뜨거운 그릇은 보호자가 맡음. 아기 단계에 요리 조작을 등록하지 않는다.
현재 아이 단계·배우자·실제 참석자를 확인.
‘처음 함께 만든 빵’처럼 중요한 경험만 앨범에 기록.
작품/기억의 동일 경험 ID를 04 기억과 08 가족 앨범이 함께 참조.
아이에게 식사 준비 노동이나 부모 고민 해결 역할을 맡기지 않는다.

11. 실수·중단·보관
실수하면 모양이 달라진 기본 결과 또는 다시 살펴보기. 필수 기본 참여에서 재료 전부 소실은 피함.
건강 피해·식중독·조리 사고 시스템은 이 기획 범위에 넣지 않는다.
중단: 소비 전이면 취소, 소비 후면 실제 완료 단계까지 저장하고 이어가기.
영구 무료 재료나 중단 반복 보상은 없음. 되돌려줄 재료 기준을 단계별로 명시.
가방은 현재 stackCap 제한이 있고 add는 넘친 결과를 버릴 수 있으므로 요리 전 결과 공간 확인 필수.
완성품이 넘치면 결과 보관함/한 회차의 대기 결과를 두어 조용히 사라지지 않게 함.
기본 완성 음식은 강제 부패와 일일 폐기 없이 보관. 당일 음식 설정은 분위기 문구로만 시작.
식탁에 차린 음식은 가방 재고에서 식탁 회차 재고로 이동. 먹기/회수/행사에 한 곳에서만 소비.
자리 회수·가구 이동·날짜 변경·행사 취소 시 잔여 음식 반환을 한 번 처리.

12. 장날·행사 연결
01 소모임: 차/간식 준비, 시식, 공동 반죽.
02 함께 일하기: 빵집 작업장에서 만드는 제품은 가게 소유와 개인 소유 구분.
03 좌판: 실제 판매 가능한 완성 음식만 판매. 제조 비용/수량/기존 하루 수입과 가격 검토.
04 기억: 처음 만든 음식·함께 고른 곁들임·의미 있는 식사.
05 작은 행사/결혼식/생일: 준비 음식에 연결. 생일 빵 도트는 자동으로 새 식용 아이템이 아님.
08 가족: 함께 만들기·아이의 모양 선택·첫 가족 식사.
09 집 공간: 차/식사/준비 자리를 실제 이용.
10 근황: 새 간식 진열·주민의 점심·요리 뒤 휴식.
11 생활 기술: 새 모양·조합·그릇 연출 배우기.

13. 요리 도트 제작 목록
재사용: 화덕·탁자·그릇·찬장, 반죽, 빵/간식/쟁반, 차 따르기,
  taste/shareFood/carryParcel/placePlate, 준비·정리·성인/아이 기본 모션.
보완: 요리별 원재료/손질 중/조리 중/완성/먹고 빈 접시 상태.
신규: 콩 요리 냄비·주걱·뒤섞는 내용물·그릇으로 덜기·냄비 젓기.
신규/보완: 반죽 성형, 뜨거운 요리 완성 김, 화덕 넣기/꺼내기,
  재료 씻기, 보호자가 조리하고 아이가 안전한 준비를 하는 두 사람 레이어.
도구/요리/인물 레이어를 분리. 인물 머리·옷·피부 유지.
방향을 쓰는 동작은 앞뒤좌우. 무방향 음식 접시/아이콘은 공통 자산.
요리별 지도용 투명 도트와 8×8 가방 아이콘, 프레임 시간과 기준점 제공.
앞서 만든 빵·생일 소품을 모든 요리 그림 대신 쓰지 않음. 실제 지원 메뉴와 그림 ID 대조.
큰 음식 사진·메뉴마다 전용 일러스트는 필수 아님.

14. 저장과 구현
기존 items.ts의 Recipe/FOODS/Inventory와 실제 제조 액션 경로를 확장.
새 요리 아이템은 types.ts의 ItemId·메뉴 이름·가방 그림·판매 목록을 함께 등록.
작업 회차: ID, 요리 ID, 선택 변형, 공급/개인 재료, 소비 여부, 단계, 시작일, 완성/지급.
차림 회차: ID, 음식과 남은 제공 분량, 자리, 실제 참석자, 소비·반환, 기록 여부.
레시피 해금: ID, 실제 배운 날/주민. 옛 레시피 접근을 잠그지 않는다.
옛 저장에는 새 상태 기본값. 현재 빵·가족 저녁·앨범 기록 유지.
요리 재생용 프레임은 영구 저장하지 않고 실제 조리 단계로 복원.
구체적인 파일 위치는 구현 전에 확인. 새 별도 엔진을 먼저 만들지 않음.

15. 구현 순서
1) 기존 빵을 새 화면에서 만들기→먹기→저장까지 유지.
2) 콩 요리 한 종류: 재료/모션/완성품/가방 공간/중단 처리.
3) 식탁 한 자리: 차리기→먹기→회수, 혼자와 가족 저녁 연결.
4) 꿀빵/과일 접시/허브 선택, 주민 취향과 배움.
5) 소모임·행사·아이·좌판·다양한 메뉴로 확장.

16. 검증 및 완료 기준
소비·지급·먹기·회수·판매·행사·재접속에 음식/재료가 중복되지 않는가.
가방 한도/중단/가구 이동/늦은 참석/부재/가족 저녁 동시 발생에도 결과가 일치하는가.
참석하지 않은 인물을 기억하거나 시도만 한 요리를 완성으로 기록하지 않는가.
아이/동물/현재 주민 취향과 실제 기능 조건을 지키는가.
미니게임·타입·저장 마이그레이션·핵심 플레이·모바일 조작을 검증.
완성 기준: 준비→요리→음식의 실제 변화→함께 먹기→집과 관계에 남는 기억까지 연결.
음식 만들기가 새 의무나 과도한 돈벌이로 변하지 않도록 현재 시간·경제와 비교.
성경 사건/비유를 요리 장면으로 재현하지 않고 본문·필사본·말씀 조각을 요리 상품/재료로 사용하지 않는다.
