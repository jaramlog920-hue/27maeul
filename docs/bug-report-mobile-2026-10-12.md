## MOB-01 · P2 · 필사본 첫 다운로드 실패 후 연결을 복구해도 같은 장을 열 수 없음

### 재현

1. 아직 유다서 본문을 받아 본 적 없는 새 브라우저 세션에서 유다서 1장 필사 완료 상태를 준비한다.

**기대:** 연결이 복구되면 본문을 다시 받거나, 새로 접속해야 한다면 저장 후 재접속할 수 있는 명확한 복구 수단을 제공한다.

**영향:** 모바일에서 첫 요청이 일시적으로 끊긴 뒤 안내대로 재시도해도 읽기 화면이 복구되지 않는다. 저장된 필사 기록이 지워지는 오류는 확인하지 않았다.

## 재현 상태 불러오기

개발 서버의 **별도 테스트 브라우저/저장 세션**에서 게임을 시작한 뒤 아래를 실행한다. 실제 사용자 저장에서 실행하지 않는다. 재현 파일은 엔진의 `serialize()` 형식이다.

```js
const store = window.__gd.store;
const { deserialize } = await import('/src/engine/save.ts');
const { CONTENT } = await import('/src/content/catalog.ts');
const text = await (await fetch('/artifacts/mobile-check/more-repro-heir.json')).text();
const game = deserialize(text, CONTENT);
if (!game) throw new Error('재현 상태를 불러오지 못함');
store.getState().load(game);
store.setState({ modal: { kind: 'talk', neighborId: 'rudy', line: '이어서 이야기해요.' } });
```

MOB-01은 파일을 `more-repro-copied.json`으로 바꾸고 마지막 modal을 `{ kind: 'readPick', source: 'copied' }`로 바꾼다. 해당 책의 본문을 아직 로드하지 않은 새 세션을 사용한다.

## MOB-03 · P2 · 짧은 모바일 화면에서 옷장 상단이 잘리고 스크롤로 복구할 수 없음

### 재현

3. 미리보기·무작위·좌우 회전 버튼을 확인한다. 위쪽으로 스크롤한 뒤 다시 확인한다.

**기대:** 옷장 전체 내용이 화면 안의 스크롤 영역에 들어가 미리보기와 모든 편집 버튼에 접근할 수 있다.

**영향:** 짧은 모바일 화면에서 미리보기를 확인하거나 무작위·회전 기능을 터치할 수 없다. 가로 화면은 앞머리 등 다른 편집 항목까지 위로 밀린다. 아래의 뒤로·이대로 입기 버튼은 보이므로 전체 게임이 막히는 문제로 분류하지 않았다. 가로 넘침 0만 검사하면 놓치는 세로 접근성 오류다.

## MOB-05 · P2 · 공동주택에 독립한 아이에게 옷장 변경이 표시되지 않음

### 재현

1. 진로가 확정된 성인 아이를 가족 화면의 실제 거주 변경 버튼으로 공동주택에 입주시킨다.
2. **나리 옷장**을 열고 머리·옷·장신구를 바꾼 뒤 **이대로 입기**를 누른다.
3. 저녁 19시 이후 공동주택 2층의 아이 모습을 확인한다.
4. 가족 화면에서 옷장을 다시 열어 저장된 미리보기와 비교한다. 같은 아이를 다시 돌아오게 한 뒤 지도 모습도 비교한다.
5. 입주 후 변경 상태를 저장 복원해 다시 공동주택 지도를 확인한다.

**기대:** 가족 옷장에서 저장한 외형이 공동주택에서도 해당 아이에게 표시된다.

**실제:** 옷장에는 청록색 양갈래 머리·목동 옷·반바지·어깨 가방이 남아 있지만, 공동주택의 아이는 갈색 머리와 기본 옷으로 그려진다. 저장은 `looks.child`에 유지된다. 동일한 외형으로 마을로 돌아오게 하면 지도에서 청록색 머리 등 변경한 모습이 정상 표시된다. 저장 복원 후에도 공동주택에서만 기본 모습이 나온다.

**영향:** 독립한 아이의 외형 꾸미기가 저장되어도 실제 만나는 장소에는 반영되지 않는다. 저장 자체가 없어지는 문제와 구분한다.

**관련 코드:**

- `src/render/renderer.ts:2912` — 공동주택 playerChild를 기본 look/name만으로 만들고 `game.looks.child`를 읽지 않는다.
- `src/render/renderer.ts:2852` — 기존 우리 아이 렌더링은 `game.looks.child`를 적용한다. 복귀 후 정상 표시와 일치한다.
- `src/engine/game.ts:4456` — dressUp은 아이 외형을 looks.child에 저장한다.

**증거:** `round-adult-child-wardrobe-changed.png`, `round-lodging-child-dressed-map.png`, `round-lodging-child-wardrobe-reopened.png`, 정상 대조 `round-child-return-dressed-map.png`, 복원 후 `round-bug-lodging-wardrobe-reloaded-map.png`. 상태는 round-results.json의 lodging-child-wardrobe/returned-child-uses-same-look에 기록.

**재현 파일:** `artifacts/mobile-check/round-repro-lodging-wardrobe.json`. 별도 테스트 세션에서 deserialize/load 후 modal을 null로 두면 저녁 공동주택 2층 지도를 바로 볼 수 있다. 지도 위치는 재현 편의를 위해 준비했으며, 실제 거주 선택·옷장 변경·저장은 버튼으로 수행했다.

**수정 후 확인할 것:** 본인 아이의 남/여 외형·색·장신구·피부, 입주 전후·저장 복원, 낮과 저녁/비 오는 날, 주민에게서 태어난 다른 공동주택 자녀의 모습 회귀 여부.
