# 27마을 가족 기능 점검 — 2026-10-08

대상은 최신 로컬 작업 폴더의 주민 가계도·결혼·출생·외형 유전·성장·은퇴 후 이사다. 동작 오류 6건과 설계 대비 머리색 유전 누락 1건을 확인했다. 아래 F04의 세 증상은 같은 인물 ID 연결 문제로 묶었다.

게임 기능은 수정하거나 배포하지 않았다. 기존 작업 파일은 보존하고 이 보고서와 재현 코드만 추가했다. 실제 사용자 저장이나 브라우저 화면으로 확인한 결과는 아니며, 게임 API·저장 왕복·React 대화창 렌더링으로 재현했다.

## F01. [P1] 이미 결혼한 주민에게 플레이어가 고백할 수 있음

- 재현: 주민 결혼 API로 루디–파피 부부를 만든다. 플레이어는 여자 모습·연인 없음·루디 하트 10개·들꽃 다발 1개 상태로 고백한다.
- 실제: `canGiveBouquet`는 차단 이유 없이 `null`을 반환하고, `giveBouquet`는 플레이어의 연인을 `rudy`로 바꾼다. 주민 계보의 `rudy.spouse = poppy`는 그대로 남는다. 한 사람에게 주민 배우자와 플레이어 연인이 동시에 연결된다.
- 원인: `src/engine/game.ts:3049`가 플레이어의 연인 여부만 확인하고 `gen.persons[대상].spouse`를 검사하지 않는다. `releasePlayerPartner`도 주민의 연인·준비 단계만 지우고 배우자 관계는 유지한다.
- 수정 방향: 주민 배우자가 있는 대상에게 고백을 거절하고, 세대교체 후 화면에 서 있는 실제 인물을 함께 확인한다.

## F04. [P1] 부모가 이사한 뒤 자녀의 결혼·출산 대화가 막힘

- 재현: 루디–파피와 웬델–틸리의 아이를 출생시키고, 게임 날짜로 성장·견습·은퇴·이사까지 정산한다. 서로 다른 모습이며 `canPair`가 허용하는 자녀 둘을 선택한다. 파피 자리의 실제 주민은 `g-0001`, 틸리 자리의 주민은 `g-0002`가 된다.
- 증상 A: 엔진에 자녀의 결혼 상담이 열려 있고 `consultFor(g, 'g-0001', …)`가 관계를 반환한다. 실제 대화창 머리에는 자녀 이름이 뜨지만 ‘이야기 들어 주기’ 단추는 없다. 상담 응원이 필수이므로 자녀의 결혼 진행이 막힌다.
- 증상 B: 별도 엔진 상태로 자녀의 결혼 준비를 만들면, 결혼식 날 두 NPC의 목표는 `{26,17}`·`{19,22}`이며 결혼 자리 `{24,19}`·`{25,19}`로 가지 않는다.
- 증상 C: 별도 엔진 상태로 자녀 부부와 침대 부탁을 만들면, 재료가 있어도 ‘아기 침대 건네기’ 단추가 없다.
- 원인: `src/features/talk/TalkBox.tsx:129`는 부모의 자리 ID를 `GenTalk`에 넘기고, `src/features/talk/GenTalk.tsx:37`은 그 ID로 상담·준비·침대 부탁을 조회한다. 관계는 생성 인물의 ID로 저장된다. 결혼 자리도 `src/engine/game.ts:559`에서 생성 ID로 지정하지만 실제 NPC 객체는 부모의 자리 ID를 사용한다.
- 수정 방향: 자리 ID↔현재 인물 ID 변환을 대화·행사·하트 조회에 일관되게 적용한다. 이름 채우기도 `neighborById`만 쓰지 말고 생성 인물의 이름을 지원한다.
- 범위: B·C는 A로 막히는 구간 이후의 연결을 따로 검증한 것이다. 일반 플레이에서 상담을 통과했다고 주장하는 결과는 아니다.

## F03. [P2] 잘못 연결된 신혼집 때문에 태어난 아기가 어느 방에도 표시되지 않음

- 재현: 루디–파피 결혼 → 침대 건네기 → 28일 뒤 출생.
- 실제: 아이 `g-0001`은 계보와 가구 자녀 목록에 있지만, 실제 첫 마을의 모든 방을 대상으로 `householdBabies`를 호출한 결과는 빈 목록이다.
- 원인: `src/engine/gen-settle.ts:46`은 `family`를 주민 ID에 있을 때만 집으로 인정한다. 파피의 집안 `teahouse`는 실제 방 소유자지만 주민 ID가 아니므로 파피를 제 집이 있는 사람으로 판정하고 신혼집을 `poppy`로 저장한다. `ROOMS`에는 `poppy` 방이 없다. `src/render/village-followup-scene.ts:23`은 `h.home === room.owner`로 아기를 찾는다.
- 영향: 화면에 아기가 없는 상태로 출생 소식·성장만 진행된다. 생성 인물끼리 결혼해 `g-0001`을 집으로 저장하는 경우도 같은 방 연결 문제가 생긴다.
- 수정 방향: 실제 방 소유자·상속된 거주지·새 터의 주택을 바탕으로 거주지를 정하고, 방이 없을 때 표시 가능한 임시 거처를 보존한다.

## F05. [P2] 손주 세대에서 부모의 외형 유전이 사라짐

- 재현: 위 F04의 자녀 둘을 주민 결혼 API로 결혼시키고 침대를 건넨 뒤 출생 정산한다.
- 실제: 부모 둘은 각각 피부·앞머리·뒷머리·윗옷·아랫옷의 외형 값 5개를 가지고 있지만, 손주에게는 `avatar`가 없다. 표시 시 `genAvatar`의 기본 외형으로 돌아간다.
- 원인: `src/engine/gen-settle.ts:54`의 `avatarOfFor`가 고정 콘텐츠의 `neighbors`만 검색한다. 생성된 부모의 ID와 `gen.persons[id].avatar`는 조회하지 않는다. 따라서 `src/engine/gen-birth.ts:53`에서 양쪽 부모 외형이 모두 빈 객체가 된다.
- 수정 방향: 생성 인물의 저장된 외형을 우선 조회하고, 고정 주민만 콘텐츠 외형으로 보완한다.
- 범위: F04의 상담 차단 이후 경로를 엔진으로 별도 검증한 문제다.

## F02. [P2] 자녀가 결혼하면 가계도에서 원래 부모와의 연결이 숨겨짐

- 재현: 결혼 전 가계도에는 아서(`carpenter`) → 루디가 있다. 루디–파피가 결혼한 뒤 가계도를 다시 계산한다.
- 실제: 계보 데이터의 `rudy.parents = ['carpenter']`는 보존되어 있지만, 화면에 쓰는 `familyGroups` 결과에는 아서 → 루디 연결이 없다.
- 원인: `src/engine/gen.ts:275`가 신혼 가구에 나온 사람을 `used`로 표시하고, `src/engine/gen.ts:279`가 기존 집안의 자녀를 `used` 기준으로 제거한다. 루디는 신혼집의 어른으로 나왔다는 이유로 원래 집안의 자녀 목록에서 빠진다.
- 수정 방향: 중복 사람 카드와 부모–자녀 연결을 구분해, 결혼·독립 뒤에도 이전 세대와의 연결을 표시한다.

## F07. [P2] 인구 정원이 찬 출생일에 예약이 삭제됨

- 재현: 침대를 이미 건네 출생 예약이 잡힌 가구를 준비한다. 출생일에 생성 주민이 정원 8명인 상태로 정산하고 저장·불러오기한다.
- 실제: `cribAsk.given = true`는 남지만 `birthDue`는 `undefined`로 지워진다. 첫 자녀도 없으므로 새 침대 부탁이나 첫 출생 예약을 다시 만드는 경로가 없다.
- 원인: `src/engine/gen-birth.ts:69`가 정원 초과와 자녀 수 상한을 같은 분기로 처리하고 출생일을 삭제한다. 설계의 ‘조건을 못 맞추면 대기’와 다르다.
- 수정 방향: 인구 정원 초과는 출생 예약을 유지하며 대기시키고, 이미 자녀 상한을 채운 상태와 구분한다.

## F06. [P3 · 기능 누락] 머리색은 부모와 무관하게 기본색으로 고정됨

- 재현: 루디–파피의 자녀를 출생시키고 부모와 자녀의 표시용 머리색을 비교한다.
- 실제: 부모는 각각 HSV `[15,60,40]`, `[5,55,45]`지만 자녀는 기본색 `[25,62,35]`다.
- 원인: `src/engine/gen-settle.ts:59`가 정수 외형 번호 5개만 전달하고, `src/engine/gen-looks.ts:9`도 색 정보를 복원하지 않는다. `GenPerson.avatar`와 저장 검증 역시 색 배열을 지원하지 않는다.
- 판정 기준: `docs/superpowers/plans/2026-10-06-plan-20-ot-village-and-generations-build.md` 작업 13에는 부모의 ‘머리·피부·색 조합’을 저장하는 요구가 있다. 이번 결과는 런타임 오류가 아니라 그 요구에 대한 구현 누락으로 구분한다.
- 수정 방향: 색 채널을 외형 타입·출생 조합·저장 검증·표시까지 연결한다.
