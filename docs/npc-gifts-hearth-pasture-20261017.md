# 선물 답변·주민 호감도·벽난로·목장 경로 (2026-10-17)

> 목장 조사 후속: 실제 일과 전환에서 입구 점유에 따른 단절을 재현했고, 타이머 방식은 제거했다. 최신 원인과 수정은 [양우리 근본 수정](pasture-root-navigation-20261017.md)을 참고한다.

## 선물
`game-store.gift`가 선물 물품 종류와 무관하게 NPC의 고정 음식용 답변을 사용했다. 먹을 것/식재료는 기존 답변을 쓰고, 양털·향초·향유 같은 비식품은 감사와 사용 답변으로 바꾸었다. 양털·향유·향초를 실제 스토어에서 선물하고 물품 차감과 비식품 답변을 확인했다. 기존 호불호·선물 보상은 유지한다.

## 호감도
`game.heartUp`에서 주민 성격 자료의 `pace`를 곱하던 계산을 제거했다. 같은 행동에 대한 기본 증가량은 모든 고정 주민이 같다. 기존 점수는 바꾸지 않는다. 하루 제한, 관계 상한, 공통 매력 보너스, 생일·선호 선물 등의 규칙은 유지한다. 모든 주민에게 같은 2점 행동을 적용하는 검사와 기존 관계·연애 검사를 통과했다.

## 벽난로와 요리
- 첫 메뉴는 요리하기/불 쬐기/먹기/닫기로 단순화했다. 중복 빵 굽기는 요리 목록의 빵으로 통합했다. 불 쬐기는 기존 그을음 모으기 기능도 있어 추위가 0이라고 막지 않았다.
- 배운 요리 모양 선택과 아직 배우지 않은 요리는 접힌 항목으로 이동했다. 배운 모양이 없으면 빈 항목도 표시하지 않는다.
- 재료 없는 음식은 선택해 재료 수를 확인할 수 있지만 제작 버튼은 `재료 부족`으로 비활성화된다. 피로·가방·해금 등 다른 막힘도 실제 이유를 표시한다.
- 재료 수는 무조건 궤짝을 더하지 않고 실제 제작이 참조하는 `stockOf`로 일치시켰다. 선택 화면의 긴 음식 설명은 제거하고 재료·시간·막힌 이유를 남겼다.
- 실제 UI 클릭으로 요리 시작/재료 차감/재료 부족 상태에서 실행 방지/음식 먹기 등을 확인했다.

## 목장 끊김 조사와 개선
브라우저는 기존 접근 거부 상태이며 사용자가 겪은 비 오는 날의 정확한 위치를 아직 전달받지 못했다. 따라서 같은 화면의 끊김을 재현했다고 보지는 않는다.

목장 내부 목표 (5,29) 주변 네 칸을 막고 (10,30)에서 NPC 경로를 찾는 재현 검사를 만들었다. 기존 `neighbors.route`는 경로가 없을 때 모든 문을 대상으로 일반 BFS를 456회 호출해 단일 측정 약 136ms가 걸렸다.

- 일반 길은 기존 BFS 그대로 찾는다. 문을 건너야 하거나 막힌 길은 문 이동을 간선으로 포함한 한 번의 BFS로 찾고, 첫 번째 문까지의 걸을 경로만 반환한다.
- 도달할 수 없는 동일 목표는 매 프레임 다시 탐색하지 않고 0.5초 후 재시도한다. 목표가 달라지면 바로 새 경로를 찾는다. 장애물이 사라지면 다시 걷는다.
- 동일 조건의 변경 후 단일 측정은 약18ms였다. CPU·검사 환경·첫 실행 비용에 영향을 받는 참고치이며 실제 FPS 수치가 아니다. `pasture-route-before.json`/`pasture-route-after.json`에 원시 결과를 남겼다.
- 집 출입, 공동 주택 계단, 집 확장 뒤 동선, 모든 주민 일정 위치의 경로 및 재탐색 대기를 검사했다. 비나 양의 그림을 없애는 변경은 하지 않았다.

## 확인
관계·선물·요리 UI 관련 검사와 경로·집 출입 관련 검사 통과. TypeScript·콘텐츠 검사·Vite/PWA 빌드 통과. 기존 저장과 다른 대화의 작업은 보존했다. 브라우저 육안 확인 및 비 오는 날 정확한 현장 재현은 미완료다.

## 선물 반응 후속 수정
사용자 요청으로 음식/비식품별 답변 구분을 없애고 모든 선물에 선호도만 반영한다. `dislikesOf`의 싫어함을 먼저 확인하고, `giveGift`의 좋아함 여부에 따라 좋아함/보통/싫어함 세 반응을 선택한다. 어느 반응도 아이템 이름·먹기·사용 용도를 언급하지 않는다. 실제 선물·호감도 검사 22개와 타입·콘텐츠·빌드 검사 통과.
