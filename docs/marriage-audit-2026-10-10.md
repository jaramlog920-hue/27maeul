# 결혼 흐름 추가 진단 (2026-10-10)

## 후속 수정

- `isSuitor`와 고백 이벤트의 조건을 통일했다. 후계자가 있으면 그 사람의 `look`으로 판단하고, 누락된 모습은 부모 설정으로 추측하지 않는다. 기존 주민은 기존 설정을 그대로 사용한다.
- 주민 정산의 이별 유예 조회를 `slotOfPerson`으로 연결해, 자리 ID로 저장된 이별 날짜가 후계자에게도 적용되게 했다. 기존 저장 형식 변경은 없다.
- `src/engine/marriage-heir-eligibility.test.ts`에 재현 3건, 고백 조건·수락, 저장 후 유예·14일 경계, 기존 주민 판정을 포함한 검사 6건을 추가했다.
- 수정 후 관련 7개 테스트 파일의 56건이 통과했고 TypeScript 및 프로덕션 빌드를 확인했다. 이번 검증은 엔진·저장 검사이며 브라우저 자연 플레이 완주 검사는 아니다.
- `extra-candidates.test.ts`의 기름 짜는 이웃 친밀 장면 검사는 수정 전 판정으로 되돌려 비교해도 같은 `openEvent` null 실패가 발생했다. 이번 변경의 회귀와 구분하며, 해당 문제는 이 수정에서 해결했다고 주장하지 않는다.
- 아래 내용은 수정 전 진단 기록이다. 배포는 수행하지 않았다.

게임 코드는 수정하지 않았다. 정상 기대값을 검사하는 별도 엔진 재현 검사를 수행했다.
자연 플레이로 세대교체까지 진행한 브라우저 검사는 아니며, 성인 후계자 상태를 구성해 실제 엔진 함수를 호출했다.

## 확인한 문제

1. `src/engine/game.ts`의 `isSuitor`는 현재 자리의 후계자 대신 원래 주민 정의의 `look`을 사용한다.
   여자 플레이어와 여자 후계자라도 원래 루디 자리라면 `canGiveBouquet`가 허용한다.
   반대로 여자 플레이어와 남자 후계자라도 원래 파피 자리라면 `notSuitor`로 차단한다.
   이는 게임의 기존 '서로 다른 모습만 연애 가능' 규칙과 불일치한다.
2. `breakUp`은 `exPartner:rudy`처럼 자리 ID로 이별 날짜를 기록한다.
   `settleOneDay`의 `cooling`은 `exPartner:g-0001`처럼 생성 주민 ID로 읽는다.
   실제 성인 후계자와 헤어진 200일 다음날(201일)에 다른 주민과 `lover`로 전환됐다.
   설계상 14일 유예가 적용돼야 한다.

## 검사 결과

- 신규 진단: 정상 기대값 3건 모두 실패해 위 두 문제를 재현.
- 기존 `marriage-slot-regressions.test.tsx`, `gen-wedding.test.ts`: 10건 통과.
- 재현 소스는 `docs/audits/2026-10-10-marriage-additional.test.ts.txt`로 보관.
- 전체 결혼 흐름이 정상이라는 의미가 아니며, 확인된 두 문제에서 진단을 종료했다.

## 수정 방향

- 연애 후보 판정과 고백 이벤트 조건이 모두 `slotPerson`의 현재 인물 정보를 사용하도록 통일.
- 이별 유예 조회에서 생성 인물 ID를 `slotOfPerson`으로 자리 ID에 매핑.
