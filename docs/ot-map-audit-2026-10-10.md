# 구약맵 진단 (새 터)

## 후속 수정·기능별 검사

이하 최초 진단 이후, 사용자 요청에 따라 갇힘 문제를 수정했다.
`canPlace`에서 새 터 야외에 있는 현재 플레이어가 배치 후에도 입구에 도달할 수 있는지 검사한다.
첫 마을과 실내 좌표에는 이 조건을 적용하지 않는다. 거부한 배치는 재료·돈·지도·저장을 변경하지 않는다.
이미 갇혀 저장된 상태를 자동 이동시키는 복구는 추가하지 않았으며, 나무를 걷어내는 기존 방법을 쓸 수 있다.

기능을 하나씩 나누어 확인했다.

- 건축·길막힘: `newland-player-access.test.ts` 회귀 검사 4건 추가. 건축·꾸미기·방 문맥 관련 4개 파일 82건 통과.
- 건물 출입: `newland-door-flow.test.ts` 4건 추가. 두 주택 슬롯과 아래·왼쪽·오른쪽 문, 저장 복원 후 출입, 야간 입장 차단과 퇴실을 확인. 출입 관련 3개 파일 24건 통과.
- 방문객: 대화·선물·입주 관련 3개 파일 18건 통과. 이번에 확인한 범위에서는 추가 수정할 버그를 재현하지 못했다.

`npm run build`의 본문 검증·TypeScript 검사·Vite 빌드를 수행했다. 큰 번들 경고가 있으며 별도 최적화 대상이다.
이번 검증은 상태를 구성한 엔진·저장 및 컴포넌트 검사다. 실제 브라우저 자연 플레이 전수 검사는 아니며, 배포하지 않았다.

## 확인한 실제 버그 하나

새 터의 포장되지 않은 잔디 위에서 플레이어를 나무로 둘러싸는 배치가 허용된다.
플레이어를 (20,20)에 놓고 `orderBuild`로 작은 나무를 (19,20), (21,20), (20,19), (20,21)에 순서대로 놓았다.
마지막 배치의 `canPlace` 결과는 차단 사유 없이 null(허용)이었다. 네 방향의 `walkDirection` 경로 길이는 모두 0이고 저장 복원 뒤에도 플레이어는 같은 위치였다.
꾸미기에서 나무를 걷어내면 복구 가능하므로 영구적인 데이터 손실로 판정하지 않는다.

원인: `newland-build.ts`의 `mustReach`는 서고·건물 문·배치한 길과 정원은 검사하지만 현재 플레이어가 선 잔디를 포함하지 않는다.
정상 기대값을 넣은 재현 검사는 실패했다. 소스: `audits/2026-10-10-ot-map-trapped.test.ts.txt`.

## 기존 검사와 실제 버그 구분

관련 7개 테스트 파일 134건 중 130건 통과, 4건 실패.
- 첫 마을 지도 높이가 실제 164로 늘었는데 기존 검사는 120을 기대했다.
- 개방 전 왕래 표식 칸은 현재 풀('.')인데 기존 검사 두 건은 길(',')을 기대했다.
- 첫 입장 연출 닫기 검사는 먼저 표시되는 말씀조각 획득 창을 고려하지 않았다. 실제 표시 순서대로 획득 창을 닫은 다음 연출을 닫도록 바꾼 별도 비교 검사 1건은 통과했다. 이를 연출이 저절로 반복되는 실제 버그로 보고하지 않는다.
비교 소스: `audits/2026-10-10-ot-firstlight-popup-order.test.ts.txt`.

게임 소스는 수정하지 않았다. 상태를 구성한 엔진·저장 검사이며 자연 플레이 전체를 완료한 검사는 아니다.
