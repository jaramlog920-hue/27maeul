# 002 — 실제 모바일 터치와 선택 표시

날짜: 2026-10-18 (한국 시각). 이전 회차 D002의 실제 포인터 경로와 화면 표시만 확인했다. 이어서 같은 화면에 있는 두 방향 조작의 적용 대상을 검사했다.

## 검증 경로와 실행

플레이 화면 → 실제 마우스/터치 pointer-down → `GameCanvas` 좌표 변환 → 스토어 `tap` → 선택 테두리/조작판 → 두 번째 입력 → 배치와 가방 변화.

- 로컬 Vite 서버 `http://127.0.0.1:4181`.
- 임시 Edge 브라우저 프로필을 사용했다. 실사용 브라우저나 저장 기록을 건드리지 않았다.
- 데스크톱 1280×960, 마우스.
- 모바일 390×844, device scale 2, 실제 touch 포인터 이벤트를 발생시키는 브라우저 에뮬레이션. 물리 휴대폰 검사는 아니다.
- 첫 마을 기본 집, 기본 붙박이 가구 유지, 놓인 작은 의자 1개와 가방의 작은 의자 1개, 확대 1.25.
- 명령: `node artifacts/detail-furniture-pointer-check.cjs`
- 결과: 데스크톱/모바일 각각 같은 칸 2회, 같은 화면 좌표 2회, 방향 조작 구분을 검사한 총 6흐름 통과. JavaScript pageerror 없음.
- 증거: `artifacts/detail-audit/002-furniture-pointer/result.json`, 같은 폴더의 화면 PNG들.

## D002 추가 확인 — 선택 표시는 있으나 반복 터치로 회수됨

데스크톱과 모바일 모두 다음 변화가 동일했다.

| 시점 | 방의 작은 의자 | 가방의 작은 의자 | 상태 |
|---|---:|---:|---|
| 누르기 전 | 1 | 1 | 새 의자 설치 대기 |
| 첫 입력 | 1 | 1 | 기존 의자에 밝은 선택 테두리, 기존 가구 조작 버튼 표시 |
| 같은 곳 두 번째 입력 | 0 | 2 | 기존 의자 회수, 새 의자 설치 대기 유지 |

- 선택 표시가 없는 문제는 아니다. 실제 화면에서 밝은 테두리와 별도 선택 가구 줄을 확인했다.
- 두 번째 입력은 실제로 같은 캔버스에 들어왔다. 모바일 이벤트는 touch, 데스크톱은 mouse로 기록됐다.
- 선택 전후 캔버스 위치·크기는 동일했다. 조작판 확대 때문에 같은 좌표가 다른 칸으로 바뀐다는 가설은 이번 조건에서 배제했다.
- 첫 입력 후 모바일 하단 조작판은 위쪽으로 커졌지만 캔버스는 유지됐다.
- 이 동작은 코드에 명시된 선택/재선택 회수 분기와 일치한다. **의도 확인 필요한 조작 위험** 분류를 유지한다.

## D003 — 새 가구 방향과 기존 가구 방향 조작을 시각적으로 구분하기 어려움

분류: **재현된 조작 문맥·안내 부족**. 회전 엔진 오류로 분류하지 않는다.

재현:

1. 가방의 작은 의자를 설치 대기한 상태에서, 이미 놓인 작은 의자를 한 번 누른다.
2. 조작판에 `작은 의자`가 두 줄로 보인다. 위쪽은 설치 대기 가구와 방향 버튼, 아래쪽은 선택한 기존 가구와 옮기기/돌리기/치우기다.
3. 위쪽의 `오른쪽`을 누른다. 설치 대기 방향만 right가 되고 기존 의자는 down 그대로다.
4. 아래쪽 `돌리기`를 두 번 누른다. 기존 의자는 up이 되지만 위쪽 `오른쪽` 버튼은 계속 눌린 상태다.

실제 수치: `heldFacing=right`, `stoolFacings=[up]`, 설치 대기 `오른쪽`의 `aria-pressed=true`. 데스크톱/모바일 모두 일치한다.

화면 근거: 두 가구의 이름이 같고, 보이는 이름 앞에는 ‘설치할 가구’와 ‘선택한 가구’를 구분하는 문구가 없다. 위 방향 그룹의 접근성 이름은 `설치할 가구 방향`이므로 내부 적용 대상과 접근성 의미는 구분되어 있다. 실제 시각 화면에서는 기존 가구가 선택된 상태에서도 다른 가구의 방향 버튼이 함께 표시된다.

코드 근거: `src/features/play/DecorateBar.tsx`의 `held`와 `sel`을 각각 그리는 두 블록, `src/store/game-store.ts`의 `setDecorFacing`과 `turnSelected`가 서로 다른 대상을 변경한다.

보완 후보: 설치 대기/기존 선택을 짧게 구분하거나 한 번에 하나의 조작 문맥만 보여 주는 선택지가 있다. 기존의 간결한 UI 기준과 관련되므로 이 검사에서 동작·문구를 수정하지 않았다.

대표 화면: `artifacts/detail-audit/002-furniture-pointer/mobile-separate-direction-controls.png`.
