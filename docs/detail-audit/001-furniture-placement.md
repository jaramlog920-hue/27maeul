## D001 — 설치할 수 없는 빈 자리를 눌러도 실패 이유가 나오지 않음

분류: **재현된 반응·안내 부족**. 데이터 유실 버그로 분류하지 않는다.

재현:

1. 꾸미기가 열린 기록에서 작은 의자를 한 개 가지고 설치를 시작한다.
2. 집의 유효한 바닥이 아닌 빈 자리(검사에서는 `{x: 0, y: 0}`)를 누른다.
3. 설치 모드와 수량은 그대로지만 안내 toast는 없고 선택 대상도 없다.

실제: `placeFurniture`가 null을 반환한 뒤, 기존 가구도 없는 경우 선택만 비우고 끝난다. 같은 조작을 다시 해도 이유를 알 수 없다. 탁자 위가 이미 차서 꽃병을 놓지 못한 경우도 처음에는 이유 안내가 없다.

근거: `src/store/game-store.ts:1584`의 설치 시도, `:1596`의 `!hit` 반환. 가구 이동 실패(`:1562`), 회전 실패(`:2733` 부근), 가방이 찬 회수 실패에는 별도 안내가 있다.

확인한 보존 성질: 실패 시 가방·가구 배열·저장 내용은 바뀌지 않는다.

보완 후보: 유효하지 않은 설치에는 짧은 일회성 반응을 제공할 수 있다. 기존 꾸미기 화면의 설명 줄은 가독성 때문에 줄인 것으로 코드에 적혀 있으므로, 상시 설명을 늘리거나 정확한 문구를 임의로 추가하지 않았다.

## D002 — 가구를 든 상태에서 겹친 기존 가구를 두 번 누르면 기존 가구가 회수됨

분류: **의도 확인이 필요한 조작 위험**. 코드에 선택 후 한 번 더 누르면 치우는 동작이 명시되어 있어 새 버그로 단정하지 않는다.

재현:

1. 집 안에 작은 의자 A를 놓아 두고 가방의 작은 의자 B로 설치 모드를 시작한다.
2. A의 칸을 누른다. B는 겹침 때문에 설치되지 않고 A가 선택된다. 설치 모드는 여전히 작은 의자를 든 상태다.
3. 같은 칸을 다시 누른다. B 설치가 다시 실패한 뒤 A가 회수된다.

실제: 방의 의자는 없어지고 가방 수량은 1→2가 된다. 설치 모드는 작은 의자로 유지된다. 가구가 삭제되거나 수량이 사라진 것은 아니다.

근거: `src/store/game-store.ts:1594`의 주석과 `:1600`의 재선택 시 회수 분기. `src/features/play/DecorateBar.tsx:64`에는 별도의 가방에 넣기 버튼도 있다.

검토 후보: 설치 중 반복 탭이 회수로 전환되는 동작을 유지할지, 이 상태의 선택·회수 구분을 더 명확히 할지 결정이 필요하다. 실제 모바일 화면에서 두 상태를 충분히 구분할 수 있는지는 아직 확인하지 않았다.

## 정상 확인

- 마지막 한 개 설치 후 수량 0, 자동 선택 모드 전환, 배치·수량의 저장 왕복이 일치한다.
- 잘못된 빈 자리와 차 있는 탁자 위의 첫 설치 실패는 가방·배치를 보존한다.
- 옮기기 취소와 꾸미기 완료는 기존 배치를 바꾸지 않는다. 완료 시 선택·이동·화면 시점 상태를 비운다.
- 실패한 이동은 이유를 알리고 취소 후 원래 배치를 유지한다.
- 가방의 같은 가구가 99개인 상태에서 회수를 시도하면 수량·배치를 보존하고 가방 안내를 보인다.
