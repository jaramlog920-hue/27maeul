# 002 — 모두 넣기의 부분 수납 경계

검사일: 2026-10-19 약 19:25~19:31 KST. 큐 2의 좁은 대상은 보관함 갈대 29개 + 가방 갈대 2개에서 모두 넣기 후 잔여 1개 처리다.

## 결과와 한계

**jsdom UI 6개 통과. 신규 게임 오류는 재현하지 않았다.** 수량 보존·부분 수납 후 버튼/상세 갱신·재시도·취소·열린 창에서의 수량 변경·serialize/deserialize 복원은 확인했다.

**실제 브라우저 검사는 게임 진입 전 환경 차단으로 미완료다.** 개발 서버가 준비됐다고 출력했지만 로컬 HTTP 요청이 응답하지 않았다. 두 번의 브라우저 진입 모두 30초 timeout, 별도 HTTP probe도 10초 timeout이었다. 서버를 권한 허용 도구로 재실행해도 동일해 이번 회차에서 브라우저 반복을 중단했다. 게임 버그로 분류하지 않는다. 모바일 픽셀·터치·IndexedDB를 통한 실제 페이지 재접속을 확인했다고 주장하지 않는다.

## 코드 근거

- `src/engine/easier.ts:136`의 `toChest`: 이동량을 요청수량, 가방 수량, `30-보관수량`의 최솟값으로 계산. 0 이하면 null, 나머지 가방 수량을 보존한다.
- `src/engine/game.ts:3697`의 `putInChest`: 수납 접근과 집 안을 확인하고 toChest 결과를 적용한다.
- `src/store/game-store.ts:2301`의 `putChest`: null이면 storageFull 안내, 성공이면 persist(next).
- `src/features/bag/StorageView.tsx:24`는 현재 선택 목록에서 n을 다시 계산하고, 39행의 모두 넣기는 n>1일 때만 나타난다. 부분 수납 뒤 잔여1이 상세에 반영됐다.

## 브라우저 차단 증거

실행한 명령: `node artifacts/detail-r2-storage-put-check.cjs` (임시 Edge 프로필, 권한 도구 허용). 첫 서버는 기본 샌드박스, 두 번째는 샌드박스 밖 실행으로 4197 포트 로컬 전용이었다. 두 번 모두 최초 page.goto에서 timeout으로 종료1. 새 게임·fixture·수납 조작에 진입하지 못했다.
