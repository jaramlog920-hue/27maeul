# 005 — 마지막 선물 한 개와 같은 날 재시도

2026-10-18 한국 시각. 큐 3 중 마지막 한 개를 준 직후의 수량·하루 제한·관계 보상·저장 복원만 검사했다. 다음 날 초기화는 다음 회차다. 게임 동작·밸런스·대사는 변경하지 않았다.

## 조건과 실행 증거

- 성장 제한을 우회하는 기존 `legacyGame(CONTENT)` 검사 도우미, 7일째 10:00. baker의 생일이 아님을 검사에서 확인했다.
- baker 관계 29점, 포도 1개. 대조 조건은 빵 없음 / 빵 2개 남음. 관계 30점 보상 경계를 동시에 넘도록 했다.
- jsdom 메모리 localStorage와 임시 Edge 프로필만 사용했다. 브라우저의 IndexedDB 저장 후 페이지를 다시 열어 ‘이어하기’까지 확인했다.
- `npm test -- --configLoader native --pool threads --maxWorkers 1 src/audit/detail-gift-last-unit.test.tsx`: 6건 통과.
- `node node_modules/typescript/bin/tsc --noEmit`: 통과.
- 서버: `node node_modules/vite/bin/vite.js --configLoader native --host 127.0.0.1 --port 4185 --strictPort`.
- `node artifacts/detail-gift-last-unit-check.cjs`: 모바일 에뮬레이션 390×844, 배율 2의 실제 브라우저 UI 두 경로 통과. pageerror 없음. 물리 휴대폰 검사는 아니다.
- 브라우저 기본 조작 모드가 아니라 일반 단추 모드로 고정했다. 조작 설정은 해당 임시 프로필에만 저장했다.

## 확인한 연결부와 실제/기대 결과

1. 대화의 선물하기 → 포도 1개 선택: 포도 1→0, gifted에 baker 한 번, 관계 29→32, 매력 경험치 0→2. 바구니 1개와 `gift:baker:3` 장면 한 번이 발생하고 선물 창이 답례 대화로 바뀐다. 기대와 일치한다.
2. 같은 날 즉시 동일 물건·다른 물건을 연속으로 재시도: 엔진 진입 함수를 반복 호출해도 게임 객체·현재 대화·저장 문자열이 그대로다. 빵 2개가 남는 조건에서도 차감·관계·경험치·보상 중복이 없다.
3. 선물 전에 포도가 이미 0개인 상태: 실패는 gifted나 관계·경험치·저장을 바꾸지 않는다. 같은 날 유효한 빵 선물은 가능하다.
4. 선물 창 취소: 물건·하루 기회·저장이 그대로이며 대화창을 닫는다. UI 검사와 브라우저 모두 확인했다.
5. 저장 복원: 포도 0개, gifted, 관계, 경험치, 바구니, 보상 수령 기록과 보상 장면이 유지된다. 포도 1개를 다시 획득한 상태를 만든 뒤에도 같은 날 baker에게 재선물할 수 없다. 실제 재접속 화면의 비활성 버튼을 터치해도 선물 창으로 진입하지 않는다.
6. 다른 주민: 소진된 포도를 smith에게 주려 하면 그 주민의 하루 기회는 남는다. 이후 빵을 주면 smith에게만 추가로 하루 표식이 기록되고 baker의 바구니는 늘지 않는다.

## D005 — 재현된 안내·사용성 부족: 비활성 선물 버튼에 이유와 재개 시점이 없다

재현 순서:

1. 포도 1개와 빵 2개를 가지고 baker에게 선물 창을 연다.
2. 포도 1개를 준다. 답례 대화에서 ‘선물하기’가 회색으로 비활성화된다.
3. 저장 후 다시 열고 같은 주민의 대화창을 확인한다.

실제: 빵 2개가 그대로 남아 선물할 물건이 있는데도 버튼에는 단순히 ‘선물하기’만 보인다. 오늘 이미 줬다는 이유나 다음 날 가능하다는 설명이 대화창에 없고, 버튼의 title·aria-describedby도 없다. 답례 대화와 재접속 후의 대화 모두 같다. 물건이 없을 때와 이미 선물한 날의 화면상 구분이 부족하다.

기대하는 안내: 예를 들어 ‘오늘은 이미 선물했어요. 내일 다시 줄 수 있어요.’처럼 실패 원인과 다시 가능한 시점을 알 수 있으면 된다. 문구와 표시 방식은 제안이며 수정하지 않았다. 게임 전체 도움말에 규칙이 있는지 여부와 별개로 해당 행동 위치에서의 안내 부족으로 한정한다.

코드 근거:

- `src/features/talk/TalkBox.tsx:75`: 하루 선물 여부와 물건 보유 여부를 하나의 canGift 값으로 합친다.
- 같은 파일 172–174행: disabled만 설정하고 두 사유의 안내를 표시하지 않는다.
- `src/engine/game.ts:2653` 부근: gifted 검사와 물건 차감 실패는 정상적으로 null을 반환한다.
- `src/store/game-store.ts:1761`: 거절된 호출은 상태를 바꾸지 않는다. 데이터 처리 오류로 분류하지 않는다.

증거: `artifacts/detail-audit/005-gift-last-unit/result.json`의 `other-gift-remains` 결과에 빵 2개, gifted, 비활성 속성, 대화창 전체 텍스트를 함께 기록했다. `other-gift-remains-after.png`, `other-gift-remains-restored.png`에서 표시를 확인할 수 있다. 첫 흐름의 `last-unit-only-*`는 남은 선물감이 없는 대조 조건이다.

## 검사 도구 보정과 미확인 범위

- 초기 jsdom 선택자는 그림의 접근성 이름까지 합쳐진 ‘포도포도 1’을 예상하지 못했다. 실제 이름을 포함하는 정규식으로 보정했다.
- 초기 브라우저 취소 선택자는 CSS `::before`의 ✕까지 접근성 이름에 들어가는 점을 놓쳐 ‘닫기’ 정확 일치로 실패했다. 실제 버튼 이름에 맞춰 수정 후 두 경로 모두 통과했다. 이를 게임 실패로 세지 않았다. 검사 중 찍힌 진단 화면은 확정 증거에 포함하지 않았다.
- 기존 선물 응답 문장 기대값 불일치는 이번 발견에 포함하지 않았다.
- 재현된 데이터 버그 없음. D005만 새 안내 부족으로 분류한다. 이번 범위의 미검증 의심이나 의도 확인 항목은 없다.
- 다음 날 초기화, 일일 관계 상승 상한, 생일 배율, 가방이 가득 찬 보상, 다른 관계 단계는 이번 검증 범위 밖이다.
- 약혼자의 결혼식 의상은 코드 주석상 일일 관계 선물과 별도의 준비 선물이다. 하루 제한 우회 버그로 세지 않았으며 의상 경로는 검사하지 않았다.
- 브라우저 대화 진입은 검사용 modal을 열어 수행했다. 실제 NPC에게 걸어가 인사하면서 추가로 얻는 관계점은 이 검사와 분리했다.
