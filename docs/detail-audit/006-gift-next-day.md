# 006 — 잠들기 전후 선물 제한과 다음 날 보상

2026-10-18 한국 시각. 큐 3의 다음 날 전환만 검사했다. 선물을 준 날 → 잠자기 취소/잠들기 → 다음 날 선물 → 저장·재접속 경계를 대조했다. 게임 동작·밸런스·대사를 수정하지 않았다.

## 조건

- 기존 `legacyGame(CONTENT)` 검사 도우미를 사용했다. baker의 선물과 하루 관계 상승 한도만 대상으로 했다.
- 단위·화면 검사: 20일 관계 26점에서 일일 관계 3점을 먼저 올리고 포도를 선물한다. 관계 32점, 일일 상승 6점, 포도 2개, 바구니 보상 1개로 잠들기 전 상태를 만든다. 다음 날 같은 선물을 주면 35점·포도 1개·바구니 1개가 기대값이다.
- 브라우저 검사: 이전 날 23→26점의 교류 후 포도 선물로 29점·일일 상승 6점. 다음 날 선물에서 처음 30점을 넘겨 바구니 보상 1개가 생기는 조건이다. 기존 보상의 중복 방지와 새 날의 정상 보상 지급을 서로 다른 조건으로 확인했다.
- 선택한 날과 다음 날 모두 baker의 생일이 아님을 단위 검사에서 확인했다.
- 임시 Edge 프로필과 jsdom 메모리 저장소를 사용했다. 실제 사용자 저장은 접근하지 않았다.

코드 근거:

- `src/engine/clock.ts`: advance는 minute만 늘리고 02:00에서 멈춘다. sleepClock만 day를 1 올린다. 자정이 지난 것을 다음 게임 날로 취급하지 않는 동작은 명시된 규칙이다.
- `src/engine/game.ts:4555`의 goToSleep: 보통/늦잠/아픈 아침이 공통 새 날 상태를 만들며 `gifted: []`로 초기화한다.
- 같은 파일 2406행의 dailyHeartGain 및 heartUp: 현재 게임 날짜와 heartDay.day가 다르면 전날 상승량을 적용하지 않고 새 날짜의 기록을 사용한다.
- `src/store/game-store.ts:2585`의 sleep: review 창일 때만 잠들고 결과를 저장한다. 취소 후 지연 입력과 잠든 뒤 중복 호출은 날짜를 추가로 넘기지 않는다.
- `src/features/talk/TalkBox.tsx:75`: 새 날짜의 gifted·보유 물건으로 canGift를 계산한다.

## 판정과 미확인 범위

이번 경계에서 새로 재현한 버그나 안내 부족은 없다. 미검증 의심·의도 확인 항목도 추가하지 않았다. 기존 D005의 같은 날 제한 사유 안내 부족은 그대로이며 이번 검사가 이를 해결한 것은 아니다.

- 대화와 잠자기 review 진입은 검사용 modal을 열었다. 선물·취소·잠들기는 실제 UI 단추를 터치했다. NPC까지 걸어가는 길과 침대 선택 조작은 이번 범위 밖이다.
- 자정/02:00은 advance 함수를 사용한 상태 검사이며, 실제 몇 시간 동안 브라우저를 켜 둔 검사는 아니다.
- 다음 날 선물감 없음 조건은 아침 지급품을 제외해 분리한 UI 대조 조건이다.
- 생일 배율, 약혼자 결혼식 의상, 여행 숙박, 새 터 침대, 가방 한도 보상, 모든 주민·관계 단계는 검증하지 않았다.
- 기존 ModalLayer의 대사 기대값 불일치는 새 버그로 포함하지 않았다. 기존 작업 변경도 유지했다.
