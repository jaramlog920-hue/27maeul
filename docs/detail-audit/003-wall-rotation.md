# 003 — 벽 끝의 2칸 가구 회전 실패

날짜: 2026-10-18 (한국 시각). 범위는 기본 집의 벽 끝 가로 2칸 식탁 회전 거절, 반복 거절, 취소, 저장 복원 후 재선택이다. 이전의 정상 회전·가구 설치·포인터 선택 검사는 반복하지 않았다. 게임 동작은 수정하지 않았다.

## 재현 조건

- 기본 집, 기본 붙박이 가구 유지.
- 식탁 위치 `{x:21,y:114}`, 방향 down. 가로 두 칸을 차지한다.
- 다음 시계 방향 right는 `{x:21,y:115}`의 벽을 침범하여 거절된다.
- 가방 식탁 1개·꽃병 3개. 설치 대기 식탁은 left, 선택한 기존 식탁은 down으로 두어 두 상태가 섞이는지도 확인했다.
- 첫 마을, 집 단계 0, 기본 확대 1.25.

## 보존 성질 — 이상 없음

- 실패 전후 식탁의 위치·방향·차지하는 칸·마감은 바뀌지 않는다.
- 방의 가구 배열, 가방 수량, 기존 선택, 설치 대기 방향이 유지된다.
- 실패만으로 저장 문자열이 바뀌지 않는다.
- 반복 거절 후 꾸미기 취소로 가구가 복제되거나 사라지지 않는다.
- 저장 후 다시 열면 선택은 초기화된다. 재선택 후 같은 회전은 같은 이유로 거절되며 식탁·가방은 그대로다.
- 실패 시 ‘그쪽으로 돌리면 자리가 모자라거나 길이 막혀요…’ 안내가 나온다.

## D004 — 다음 90도가 막히면 허용되는 180도 방향에도 선택 회전으로 갈 수 없음

분류: **재현된 조작 제약 / 의도 확인 필요**. 데이터 손실이나 저장 오류로 분류하지 않는다.

재현:

1. 위 조건의 식탁을 선택하고 ‘돌리기’를 누른다.
2. down→right만 시도하다 벽 때문에 거절된다.
3. 다시 눌러도 같은 right를 시도하므로 up으로 넘어가지 않는다.
4. 한편 같은 자리의 up 후보는 가로 두 칸으로 down과 동일한 차지 칸이며 배치 검사에서 허용된다.

상태 검사에서는 `placement(..., 'right') === null`, `placement(..., 'up') !== null`, down/up footprint 동일을 확인했다.

실제 화면에서는 ‘치우기’로 회수한 뒤 가방 식탁을 고르고 ‘위’를 선택하여 같은 자리에 다시 놓으면 up 배치가 된다. 가방 식탁은 1→2→1로 돌아오며 손실은 없다. 우회 조작까지 실제 터치/버튼 입력으로 확인했고 가구 방향을 상태에 강제 주입하지 않았다.

근거:

- `src/engine/room.ts:36`: `TURN`은 한 번에 시계 방향 다음 값만 고른다.
- `src/engine/room.ts:187`: 선택 가구의 다음 방향만 배치 검사한다.
- `src/store/game-store.ts:2726`: 거절되면 선택·방향을 바꾸지 않는다.
- `src/features/play/DecorateBar.tsx`: 선택한 가구에는 단일 ‘돌리기’ 버튼이 있고, 직접 방향 선택은 설치 대기 가구용이다.

검토 사항: 막힌 중간 방향을 건너뛰어도 되는지, 선택 가구도 직접 방향을 지정할 수 있어야 하는지, 현재의 단계별 시계 방향 규칙을 유지할지 결정이 필요하다. 이번 검사에서 조작이나 규칙을 바꾸지 않았다.

우회 배치 화면: `artifacts/detail-audit/003-wall-rotation/mobile-reinstalled-up.png`. 빠르게 우회하면 이전 실패 toast가 잠시 남는데, 이번 회차에서는 기존 표시 시간 안의 일시 상태만 관찰했으므로 별도 버그로 단정하지 않았다.
