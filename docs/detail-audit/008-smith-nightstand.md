# 008 — 대장장이의 협탁을 받아 실제 상판으로 사용하기

2026-10-18 한국 시각. 사용자 추가 요청 ‘대장장이에게서 설치할 수 있는 가구, 실제 사용까지’를 우선 적용했다. 특정 가구 이름은 아직 전달되지 않아 현재 코드에서 대장장이 smith가 주는 설치 가구인 협탁을 먼저 골랐다. 게임 동작·밸런스·대사·그림은 수정하지 않았다.

## 대상과 조건

- 현재 `MILESTONE_GIFTS.smith`의 설치 가구 보상은 하트 9개의 협탁이다. 3개 때의 brightLamp는 소지 도구이므로 이번 설치 가구 검사와 분리했다.
- 대장장이의 일반 상품 판매로 가정하지 않았다. 실제 현재 경로인 관계 보상으로 협탁을 받았다.
- 초기 상태: `legacyGame(CONTENT)`, 20일 10:00, 대장장이 관계 89점, 빵 1개·꽃병 1개, 대장장이의 이야기 관문은 이미 본 검사 상태. 실제 대화창 → 선물하기 → 빵을 주어 92점이 되면서 협탁 1개를 받는다. 89점까지 자연 플레이를 반복한 검사는 아니다.
- 기본 집 붙박이 가구를 유지했다. 협탁 설치 `{20,112}`, 다른 사용 위치 `{22,113}`, 기록자 `{20,114}`.
- 협탁은 코드상 ‘위에 작은 물건을 올릴 수 있는 한 칸 가구’다. 별도의 수납·생산 기능이 있다고 가정하지 않고 상판으로 실제 사용했다.
- 실제 사용자 저장은 건드리지 않았다. jsdom 메모리 저장소와 임시 Edge 프로필의 IndexedDB만 사용했다.

## 실제/기대 결과

1. 협탁 보상은 한 개, giftsGot에 협탁, `gift:smith:9` 장면이 기록된다. 설치 후에만 가방 협탁이 1→0이 된다.
2. 협탁 위에 놓은 꽃병은 가방 1→0, 방 안 한 개, `on:true`가 된다. 재접속해도 협탁·꽃병 위치와 on·수량이 같다.
3. 재접속 후 꽃병을 선택해 옆 바닥으로 옮기면 협탁은 원래 칸에 남고 꽃병만 이동하며 on이 지워진다.
4. 꽃병과 빈 협탁을 각각 회수하면 가방에 각각 한 개가 돌아온다. 다시 접속해 다른 칸에 설치하고 꽃병을 올려도 최종 수량은 각각 한 개씩이다.
5. 협탁을 직접 지정한 엔진의 moveFurniture는 위 꽃병까지 함께 옮길 수 있고 재료·가방 수량을 바꾸지 않는다. 아래의 화면 선택 제약과 구분했다.

확인한 경로에서는 소실·복제·저장 불일치가 없었다.

## D006 — 재현된 조작 제약 / 의도 확인 필요: 물건을 올린 한 칸 협탁을 직접 선택할 수 없음

재현 순서:

1. 협탁 한 개를 놓고 그 위 같은 칸에 꽃병을 올린다.
2. 배치를 끝내 저장 후 다시 접속하고 가구 배치를 연다.
3. 협탁 칸을 탭한다.
4. ‘옮기기’를 눌러 다른 칸을 탭한다.

실제: 꽃병이 선택되고 toolbar에 ‘꽃병’만 표시된다. 옮기기는 꽃병만 바닥으로 옮긴다. 협탁은 한 칸이라 꽃병 없는 다른 점유 칸을 누르는 방법도 없다. 밑 가구를 고르는 선택지는 현재 toolbar에 없다. 협탁까지 옮기려면 꽃병을 먼저 따로 치우거나 옮긴 다음 협탁을 선택해야 한다.

비교: 엔진은 협탁과 위 물건의 동시 이동을 지원한다. 사용자가 이 기능을 한 칸 가구에서도 사용할 수 있어야 하는지는 의도 확인이 필요하다. 넓은 탁자의 빈 칸 선택 경로(004)와 다르다.

데이터 오류나 물건이 없어지는 버그로 단정하지 않는다. 위/아래 대상 선택을 제공하거나 ‘위 물건을 먼저 옮겨 주세요’ 같은 안내를 고려할 수 있지만, 어떤 변경도 하지 않았다. 위 물건부터 선택하는 규칙 자체와 반복 탭 회수(D002)는 기존 사항이며 여기서는 한 칸 상판의 통째 이동 접근 제약만 추가한다.

코드 근거:

- `src/engine/furniture-defs.ts`: nightstand는 1×1, solid, surface:true다.
- `src/engine/room.ts`의 removal: 같은 칸의 위 물건을 우선 반환한다.
- `src/store/game-store.ts:1595` 부근: 탭 선택은 removal(...)[0]으로만 결정한다. 같은 대상 재탭은 밑 가구 선택 순환이 아니라 회수다.
- `src/features/play/DecorateBar.tsx`: 선택된 가구 하나에 대한 이동·회전·회수만 제공한다.
- `src/engine/game.ts:4932` 부근: moveFurniture는 surface 가구와 그 점유 칸의 on 물건을 carried 목록으로 함께 처리한다.

## 미확인 범위와 다음 대상

대장장이와 관련된 가구 전체 검사가 완료된 것은 아니다. 다른 경로의 가구·배운 마감·수납/생산 가구·다른 집·가방 한도·겹친 작은 물건 종류는 일반화하지 않았다. 선물 전 대화 진입과 꾸미기 진입은 검사 modal/상태를 열었고, 그 후 선물·가구 선택·설치·이동·회수는 실제 UI를 사용했다.

다음은 대장간에서 배우는 나무통의 마감(hookFinish) 경로다. 원래/배운 모습 선택 → 설치 → 실제 클릭 반응·기능 안내 → 회수/재설치 → 저장 복원을 검사한다. 나무통에 수납 기능이 있는 것으로 가정하지 않고 현재 정의·안내·실제 반응을 대조한다. 사용자가 특정 가구를 알려주면 그 가구를 우선한다. 아이의 helper/adult·예약 경계는 남겨 둔다.

반복 heartbeat 수신은 별도 검사 실적으로 세지 않았다. 007 이후 이 보고서의 한 경로만 새로 검증했다.
