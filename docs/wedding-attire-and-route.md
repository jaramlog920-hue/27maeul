# 예복 구매·선물·결혼식 착장과 현재 결혼 경로

2026-10-17 사용자 요청: 기존4종은 기본 옷에 추가하고 정장/드레스4종을 별도로 제작. 장날 구매, 약혼자 선물 후 결혼식 착장, 가방에 가진 유저 예복 선택을 연결한다.

## 완료한 연결

- 기존 세이지 조끼·아이보리 겉옷·아이보리 리본 옷·장밋빛 레이스 옷을 TOPS 끝18~21번에 추가했다. 캐릭터 만들기/가족 옷장 목록이 같은 TOPS를 읽어 바로 선택 가능하다. 기존0~17번·기존 아래옷/색/저장 번호를 보존한다.
- 새 검정 턱시도/흰 재킷 정장/흰 벨라인 웨딩드레스/로즈 레이스 드레스는 독립 ItemId4종과 원본 크기의4방향/서기/인사 도트다. 재킷 라펠·흰 셔츠·넥타이/나비넥타이·바지, 드레스의 잘록한 허리와 넓은 치맛단을 구분한다. 얼굴·머리·피부·짧은 손·발은 원본을 유지한다.
- 장날(7의 배수 날짜)의 기존 거래 경로와 같은 재고/닢/가방 검사로 구매한다. TradeBoard ‘결혼 예복’ 묶음에서4종 모두 각180닢이다. 새 구매 해금/강제 구매 조건을 만들지 않았다.
- 예복은 약혼 상태의 실제 상대에게만 ‘선물하기’로 건넬 수 있다. 하루 호감도 선물과 별도 준비 선물이므로 그날 일반 선물을 했어도 버튼이 열린다. 예복1개를 가방에서 빼고 현재 세대 사람 ID에 연결한다. 호감도·결혼 일정·정상 선물의 하루 제한을 바꾸지 않는다. 다시 선물하면 마지막으로 받은 예복을 입는다.
- 실제 결혼 tick에서 그 상대가 받은 옷을 해당 상대 자리/결혼 날짜로 고정한다. 플레이어에게 예복이 있으면 장면을 열기 전에 보유품만 고르는 창이 뜬다. ‘평소 옷으로 참석’도 가능하며, 가진 예복을 입어도 소모하지 않는다. 선택은 해당 결혼식에만 저장한다. 없으면 평소 옷으로 진행한다.
- 실제 플레이어/상대 모습에 렌더링용 예복 표식만 복사해 결혼식 공통 렌더러에 전달한다. 평소 avatar/looks/옷장은 변경하지 않는다. 실제 파트너와 현재 이사 온 손님을 보존한다. 마일로 인사·올리버 앉기·루디 걸음에서도 예복이 유지된다. 오스카/올리버/마일로의 원래 NPC 머리도 유지한다.
- 앨범 사진에도 같은 실제 착장을 전달한다. 저장·로드 후 선택/상대 착장을 유지한다. 미리보기/다시보기에서는 옷 선택 창이 뜨지 않고 저장이나 앨범을 쓰지 않는다. 다시보기에서 해당 결혼 날짜의 착장 기록을 읽는다.

## 현재 연애→결혼 조건 (이번 작업에서 값 변경 없음)

1. 새 진행은 신약50장에 후보 기능,60장에 고백/연애,90장에 결혼 기능이 열린다. 이전 진행 저장은 기존 해금을 유지한다.
2. 호감도80/100(8하트)에서 장날에 산 들꽃 다발30닢을 연애 가능한 상대에게 건네면 고백하고 연인이 된다. 다른 상대가 있거나, 상대에게 배우자가 있거나, 헤어진 뒤14일 유예 중이면 고백할 수 없다. 후보와 플레이어의 모습/현재 세대 eligibility 판정도 기존 규칙을 따른다.
3. 새 연애는14일 이상 경과,이번 관계 데이트3회 이상,세 번째 데이트 뒤 연인 이야기 완독이 있어야10하트 상한이 열린다. 그전에는90점까지다. 데이트3회는 서로 다른 세 장소를 뜻하지 않는다.
4. 호감도100/100,집 확장1단계 이상,결혼 기능 해금,약속의 끈150닢을 갖추고 끈을 건네면 약혼한다. canGiveCord의7일 검사도 남아 있으나 새 고백은 bondRequired:true여서3번의14일 조건까지 만족해야 한다. 이전 연애 저장의 일부는 기존 조건을 유지한다.
5. 약혼한 날보다 뒤인 다음 장날에 잔치가 잡힌다. 장날은7일 간격이다. 해당 날18:30 이상21:00 미만에 광장 모닥불 주변4칸 이내로 오면 실제 결혼 상태로 바뀌고 결혼식 장면이 열린다. 약혼 당일이 장날이어도 다음 장날이다. 놓친 결혼 날짜는 잠을 자고 다음 날로 넘어갈 때 다음 장날로 조정한다.

예:21일 고백→35일까지14일/데이트3회/이야기/100점/필사90장/집 확장을 충족하고35일 약혼→42일 결혼. 날짜만 지나면 자동으로 청혼 조건이 충족되는 것은 아니다.

근거: engine/romance.ts, game.ts의 canGiveBouquet/canGiveCord/giveCord/weddingToday/marry 및 tick, feature-rules.ts, calendar.ts. 설명 중 수치는 게임 날짜와 닢이며 현실 날짜/금액이 아니다.

## 검사 및 미리보기

구매 날짜/가격/가방,실제 약혼자 제한,하루 선물 뒤 실제 버튼,소비/비소비,실제 결혼 tick,선택→공통 렌더러→앨범 입력,저장 복원,미리보기/다시보기 무변경,기본 옷 번호 및 원본 머리/손/발 검사를 수행했다. 최종9개 파일1,801개 통과(wedding-attire-final-tests.log), 추가 실제 결혼 tick 검사6개 통과(wedding-attire-tick-test.log), 전체 사전 검사·TypeScript·Vite/PWA 빌드 통과(wedding-attire-build.log). 기존 jsdom canvas 미구현 경고/대형 청크 경고와 성공 결과를 구분한다.
