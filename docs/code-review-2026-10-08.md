## 현재 재현되는 문제

### 1. P2 — 새 터의 책상을 키보드·조이스틱으로 열 수 없다

- 위치: `src/engine/game.ts:811`의 `interactableAt`, `interactTile`, `pressTile`.
- 새 터 서고 책상 앞 `(16,33)`에서 위를 바라보고 있으면, 책상 `(16,32)`을 클릭할 때는 `otDesk` 표적이 정상적으로 생긴다.
- 같은 상태에서 스페이스가 쓰는 `interactTile`은 `null`, 조이스틱이 쓰는 `pressTile`은 책상이 아닌 현재 서 있는 `(16,33)`을 반환한다.
- 원인: 새 터 지도에서는 입구 표식을 제외하고 `interactableAt`이 바로 `false`를 반환한다. 장소와 시설을 클릭으로 찾는 경로가 공통 상호작용 판정에 연결되지 않았다.
- 영향: 마우스·화면 터치로 되는 장소 이용을 키보드와 조이스틱에서는 할 수 없다. 재현은 서고 책상으로 확인했다.
- 수정 방향: 새 터 장소·시설 판정을 클릭과 앞칸 상호작용에서 함께 사용한다.

### 2. P2 — 책을 바꾸면 정성 필사 조건을 잊고 도장을 준다

- 위치: `src/engine/copy-ways.ts:137`의 `careFor`, `finishCare`; `src/store/game-store.ts`의 `copyTypo`, `copyPuzzle`, `commitVerse`.
- 마태복음 1장의 첫 절을 퍼즐로 마친 뒤, 마가복음에서 한 절을 퍼즐로 쓰고 마태복음으로 돌아와 남은 절을 직접 쓰면 `careDone`에 `mt:1`이 들어간다.
- 원인: 진행 중인 장의 오타·퍼즐 기록이 `copyCare` 한 칸에만 있다. 다른 장 기록으로 덮이면 이전 장을 마칠 때 `careFor`가 오타 0·퍼즐 없음으로 새 기록을 만든다.
- 영향: 전체를 직접 쓴 장에만 줘야 하는 정성 도장이 잘못 지급된다. 여러 책을 번갈아 쓰는 정상적인 사용에서 발생하며, 퍼즐 수고 비율도 이전 장의 기록을 잃을 수 있다.
- 수정 방향: 진행 중인 기록을 책·장별로 보존하고 완료한 장의 기록만 정리한다.

### 3. P2 — 자동 저장이 기록한 도감·업적을 실행 중 상태에 반영하지 않는다

- 위치: `src/store/game-store.ts:1338`의 `frame`, 같은 파일의 `persist`; `src/engine/game.ts`의 `recordProgress`.
- 닢 500·미기록 업적 상태에서 20초 자동 저장을 실행하면 저장 본문에는 `coins500`이 생기지만 `useGame.getState().game.achieved`에는 없다.
- 원인: `persist`가 도감·업적을 더한 새 게임 상태를 반환하지만, 자동 저장 호출은 반환값을 사용하지 않는다. 모달이 열린 경우뿐 아니라 일반 프레임에서도 이후 `tick`이 원래 상태로 진행한다.
- 영향: 도감·업적 화면이 실제 저장과 달라지고 같은 업적 알림이 반복될 수 있다. 창을 숨기거나 닫을 때 `Play`가 실행 중 상태를 직접 저장하면 자동 저장에서 추가한 기록도 다시 빠질 수 있다.
- 수정 방향: 자동 저장 결과를 실행 중 상태와 이후 프레임 계산에 반영한다.

### 4. P3 — 저장 마이그레이션이 사용자가 쓴 메모까지 바꾼다

- 위치: `src/engine/save.ts:341`의 `deserialize` 문자열 치환.
- 현재 버전 저장의 메모 `innkeeper, lambFound: 내가 직접 쓴 메모`를 저장·불러오기하면 `apothecary, lambClover: 내가 직접 쓴 메모`로 바뀐다.
- 원인: JSON을 파싱하기 전에 저장 전체 문자열에서 옛 주민·사건 이름을 치환한다. 키와 식별자뿐 아니라 사용자 입력 값에도 적용된다.
- 영향: 해당 영문 문자열을 포함한 사용자 메모가 의도와 달라진다. 일반 한국어 메모가 모두 변하는 문제는 아니다.
- 수정 방향: JSON 파싱 후 필요한 식별자 필드와 키만 옮기고 사용자 입력은 그대로 둔다.

### 5. P3 — 식탁을 비운 뒤 반응에 다른 음식 이름이 나온다
